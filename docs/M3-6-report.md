# M3-6 · 以 Animenz 真演奏为标准：音色标定与"钢琴类"新音色

触发：用户指出我拿来当"原曲"的那份音频听着奇怪，并提供真正的演奏视频
（`【Animenz】STYX HELIX…钢琴版.mp4`），要求以它为**标准**。

## 1. 先证伪："原曲录音"是另一份东西

| | 时长 | 与谱面时间轴的最佳对齐 | 结论 |
|---|---|---|---|
| `build/styx_helix_full.wav`（旧"原曲"） | 281.4 s | — | 乐谱渲染/另一版本 |
| `build/animenz_styx_helix.wav`（视频抽取，48kHz→44.1k 单声道） | 298.7 s | `scale≈1.000, lag=5.76s, r=0.08` | **不是同一演奏的不同速度** |

`tools/align-reference.mjs` 做尺度+偏移网格搜索：同一演奏的不同速度应当 r>0.5；实测 0.08，
说明结构不同 → 旧文件不能当标准，改用视频抽取的音频。

## 2. 音色差在哪：1/3 倍频程能量占比（dB）

| 频带 | Animenz 真演奏 | 旧 strings | 新 piano（本轮） |
|---|---|---|---|
| 320–640 Hz（琴体） | **−3.2** | −11.9 | −10.8 |
| 640–1280 | −8.9 | −13.1 | −13.3 |
| 1280–2560 | −14.3 | −22.6 | −20.6 |
| 2560–5120 | −25.8 | −37.1 | **−24.6** |
| 5120–11000（空气） | −40.1 | −54.8 | −26.7 |

两条对照窗口内容本就不同（不同编曲），这组数只能读**趋势**：旧音色高频塌 11–15 dB
（"没有空灵"的量化形态），新音色把 2.5–5 kHz 拉平；5–11 kHz 现在**高于**参考 13 dB（偏亮），
若听感"刺"，调 `hfGain`/`strikeGain` 即可。

## 3. 新音色怎么做的（`src/synth/synth.mjs`）

`pianoVoice()`：非谐加性合成 —— 22 个部分音，f_k = k·f0·√(1+B·k²)（B=1.2e-4），
幅度 k^-0.85，160–800 Hz "琴体"加权 ×1.7、高频 shelf ×1.9、部分音频率上限 9 kHz；
每个部分音独立 t60（低频 3.4 s / 高频 1.7 s / 下限 0.55 s）；另加 9 ms 锤击瞬态。
`schroederReverb()`（4 梳状 + 3 全通，RT60 1.3 s，混入 0.22）补厅堂尾巴 —— "空灵"的另一半；
其后接 DC 阻断（并联梳状会积累直流，实测把自检"最强谱峰"拉到 0 Hz、音准误差报 100%）。

## 4. 接线与验收

- 旋律层默认音色：流水线 CLI `--melody piano`（库默认仍是 `strings`，不破坏既有契约与测试）；
  数据包实测 `piano 1385 / bell 254 / bass 1276`。
- 资源包：287 个采样、zip 4.12 MB，已同步客户端；`render-all` 对 piano 允许"最强峰=整数倍泛音"
  （真钢琴 2/3 次分音常比基频强，实测 C#4）。
- 全量单测 **255/255**；`lint-pack` 通过；无头 e2e lo/600 刻 9 项全绿（MSPT 7.2 ms）；已装包。
- 新工具：`tools/align-reference.mjs`、`tools/preview-render.mjs`
  （离线混音，`--mode true|folded --melody piano|strings --from/--to`）。
