# M3-15 · 力度是怎么编排的（可编辑的段落解读）

**用户提问（2026-09-15）**："我想知道你是怎样编排力度的——演奏家多是按情感、乐曲某段特点来区分力度，
从而体现自己对琴曲的独特理解。"

这篇文档就是答案：**现在的口径是什么、它是怎么算出来的、哪些是"测量"哪些是"解读"、
以及你想改的时候改哪个文件**。

## 1. 三层口径（从"测量"到"解读"）

| 层 | 输入 | 算法 | 输出 | 性质 |
|---|---|---|---|---|
| ① 逐音测量 | 源曲音频（`build/styx_helix_full.wav`） | 每颗音在**它自己的音级 + 自己的八度**上的短时窄带能量（100ms 窗，从音符起点对齐） | `velocity` 0..1 | 纯测量（M0 T5b） |
| ② 乐句级 | ① 的逐音值 | ±0.75s 时间窗**截尾均值**（去两端 10%）→ 按 p10..p90 压到 52..104 | `velMidi` 1..127 | 平滑（去掉"逐音随机强弱"） |
| ③ 段落解读 | 源曲**响度包络** + ② | 全曲切 19 段；每段取"段电平"（该段响度在全曲的分位排名 0..1）；段内走向用 ② 的弧线；两者按 55% / 45% 混合 → 压到 56..104 | `velMidi` 1..127 | **解读**（"这一段该多强"） |

② 解决的是"同一句里的音忽强忽弱"（上一轮判负的原因：相邻音跳变中位 17 级、26% 跳 32 级以上）；
③ 解决的是"整首曲子没有结构起伏"——**段电平来自乐曲本身**（前奏弱、副歌强、尾声收），
这正是演奏家"按乐曲某段特点"分配力度的机器版。

## 2. 段表（可手改 = 你的理解）

`build/dynamics-sections.json`（每次跑 `node tools/dynamics-report.mjs` 重新生成；
**改完不用重跑报告，直接重渲染即可**）：

```json
{ "sections": [
  { "start": 0,    "end": 19.25, "level": 0.06, "label": "弱（安静段）", "loudnessDb": -25.8 },
  { "start": 19.25,"end": 37.5,  "level": 0.70, "label": "中强",       "loudnessDb": -16.5 },
  ...
] }
```

`level`（0..1）就是"你认为这一段该多强"。把它改掉，重跑一次渲染/重生成数据包，力度立刻跟着变：

```bash
node tools/render-ensemble.mjs --melody salamander --dynamics interpret --name my_take
# 或回接数据包： node src/arrange/arrange-all.mjs --dynamics interpret && （6 条 emit）&& 装包
```

（`--dynamics interpret` 目前用在**离线渲染**；数据包装配走 arrange 链，等用户拍板后再默认开启。）

## 4. 演奏家还会做、而我们**还没做**的（如实声明）

| 演奏家的手段 | 我们现在的状态 |
|---|---|
| 段落对比（弱起/副歌推上去/尾声收） | ✅ 本轮做了（段电平） |
| 乐句内部的渐强渐弱、落句 | ✅ 部分（段内弧线 = 平滑后的实测走向） |
| 声部平衡（旋律突出、伴奏让路） | ⚠️ 只有全曲固定的层增益，没有"按段调整" |
| 呼吸/断句/自由速度（rubato） | ❌ 完全没做（节奏严格按谱面） |
| 触键与踏板（连奏/断奏、延长音） | ❌ `sta` 短奏采样已备好但没接线；踏板还没建模 |
| 高潮的"顶点音"刻意强调 | ❌ 没有单独的重音规则（可加：乐句最高音/长音 +N） |

想往"更像人"再走一步，优先级建议：**顶点音重音 → 按段调整声部平衡 → 断奏/踏板**。
前两项都能在现有 `dynamics-sections.json` 上扩展，不需要动数据包结构。

## 5. 附：「恒定力度」那 0.35 到底是什么（2026-09-15 追查）

用户问："现在的恒定力度版本其实是不是就是根据原曲弹奏的强弱来做的？"
**答案是：旋律不是；只有打击乐是。** 逐条查证（`build/machine_pipeline.csv`）：

| 声部 | 音符数 | `volume` 取值 | 来源 |
|---|---|---|---|
| 旋律 harp | 1639 | **全部 0.350** | `src/arrange/fold.mjs` 的 `volumeFallback = 0.35`（基线 CSV 没有 volume 列，这里兜底）——**和演奏无关** |
| 贝斯 bass | 1276 | 0.35×1166、0.297×64、0.253×33、0.215×10、0.183×3 | 0.35 兜底 + 延音重复触发 `×0.85^k` 的**机械衰减**（sustain.mjs），不是测量 |
| 打击乐 | 138 | 0.336…1.000（逐颗不同） | **是测量**：`percussion.mjs` 的 `volume = 起音强度`（从音频量出来的） |

历史沿革（为什么是 0.35）：v3 时代的 `volume` **确实**来自原曲——"每颗音 0.12s 窗的整段混音 RMS
按 p10/p90 映射到 0.35–1.0"（见 `DISCUSSION-C-music.md` §4.2，均值 0.64、两端截断严重）。
但那个口径量的是"**整段编曲**有多响"（鼓/贝斯/人声都在里面），同一步里所有音共用一个值；
M0 换成"每颗音自己的音级+八度上的窄带能量"后，结果落在 `velocity` 列（199 个不同值，**现在数据包不消费它**），
`volume` 就退化成了兜底常量。

所以原曲进到机器里的信息目前是：**音高 / 节奏 / 哪些音（转谱）、延音时长（sustain）、打击乐强度**；
演奏的**强弱**这条线，只有 `velocity` 列里有，且只在离线渲染（乐句级 / 段落解读）里被用过。
