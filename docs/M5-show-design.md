## 0. 一句话

把这条 2334 格长的机器当成一条**冥河**：音乐是河上的一道光，每颗音符是河面一次**心跳**，
两条**螺旋**缠着这条河推进，每次唱到 **"Restart"** 就整条崩解、从源头重亮一次。

歌名给了全部语言：**Styx**（亡者之河）＝河道与水流，**Helix**（螺旋）＝时间回环，
而 Re:Zero 的歌词本身就在反复出现「重启 / 死局 / 空环」这三个词义（原文与逐字时间见你本机的歌词数据，本仓库不放歌词原文）。
不是"加一堆好看的特效"，而是让**每一个视觉元素都能对上一句歌词**。

## 2. 这条机器给了什么（设计的**事实**基础，非观感）

| 事实 | 实测值 | 出处 |
|---|---|---|
| 音符数 | 3044 | `build/nbmachina_machine_map.csv` |
| 机器尺寸 | x 0–2333 格、25 个音高行（z −9..15）、单层 y=110 | 同上 |
| **播放头恒速** | **x = 8.3341·t − 32.784**（残差 max 0.63 格 / rms 0.29 格） | 对 3044 个音位做最小二乘 |

| 时间轴 | 母版 t=0 = 谱面 0s；第一颗音 **3.917s**，最后一颗 **283.858s**（4:43.9） | 机器映射表 |

| 密度 | 单刻最多同时 6 颗音；力度中位 95（q10 75 / q90 107）；音高 32–104 | 同上 |
| 重音 | 按力度推出的"重音点" **141 个**（约 2.0s 一个，≈ 小节级） | `show/styx_helix.show.json` 的 `accents` |
| 段落 | 19 段响度曲线 → 归并成 **10 场** | `build/dynamics-sections.json` + 歌词句首 |
| 当前世界与坐标口径 | 世界 `StyxHelix水世界`，机器原点 **(0,110,-9)**、49 段；甲板 y=110、**音符盒 y=111**；粒子锚点 = `(x+0.5, y+1.2, z+0.5)`（与 mod 现在那颗 NOTE 粒子完全一致） | 存档 region 扫到 `note_block` + `nbm_*`；`redo.mcfunction` 窗口 `0 -12 783 15`…（详见 §7.0） |

**从"恒速"推出的第一条设计结论（很重要）**：
机器是传送带，**本片不存在固定机位**。所有镜头都是"跟拍"——镜头语言的变化只能来自
**跟拍的距离／高度／侧偏／焦距／朝向（顺流看未来 or 逆流看已弹过的河）**。
这也意味着**节奏感不靠镜头切，靠"河上光的东西"自己走**：光流速度恒等于音乐速度，永远不会飘。

## 3. 硬约束（沿用你定稿的口径 + 2 条新的）

前 6 条逐字来自 `nbaurora/docs/visual-spec.md`，不许偏离：

1. 方块扩散**从音符盒一样大开始**（半边长 0.5 格），随速度**等比例**放大到 ~2.2×，不许一开始就大于方块。
2. 棱边恒定细描边（块宽的 3~4%）：不随扩散变粗，也不许细到看不见。
3. 涟漪 = 表面被流星击中、像水波荡开、**要连贯**：单条连续环，不许断点、不许一次三圈。
4. 粒子/火花**照搬**（烟花绽放那套），不重做、不换素材。
5. 音符盒表面发光与"方块扩散"**同一条生命周期**，不许另加光斑 / 玻璃板 / 雾球 / 光晕罩。
6. 所有元素共用同一条 easeOut 时间轴，**同起同落**；整体连贯顺滑。

本次新增 2 条（针对这首曲子）：

7. **颜色只用 5 支**（见 §5）：冥河青 / 螺旋紫 / 苍白白 / 血朱 / 暖金。彩虹是"霓虹预设"时代的语言，
这首曲子是黑白＋青＋紫，血朱只给"死"这个母题与重击（全曲占比 < 8%），暖金只在最后 40 秒出现。
8. **不加屏幕特效**：不加屏幕闪白、不加镜头方向的光斑、不加滤镜层。所有光都必须**在世界里有位置**，
   能被飞行穿过、能被机器挡住——这样它才像"河水"，不像"后期叠上去的"。

## 4. 元素清单（每个元素：观感 → 数据来源 → 命令族 → 曲线）

### 4.1 逐音心跳（主角，每颗音 3 条命令）

| # | 元素 | 观感 | 命令族 | 生命周期曲线（刻为单位，客户端 20 tps） |
|---|---|---|---|---|
| ① | **描边方块** | 12 条棱从音符盒大小起等比例扩散到 2.2×；点密度够高所以是**连续的细线**，不是一串珠子 | `custom-conditional`（体素格 + 布尔筛选，**一条命令画整个 12 棱**） | 尺寸 `k/(1+t/9)`；alpha `1−t/27`；生命 28 刻 |
| ② | **表面涟漪** | 甲板表面一圈连续波纹，先快后慢扩到 1.85 格 | `custom-polar-parameter`（`s2=0` 即水平环） | 半径 `0.5+1.35·(1−e^(−t/11))`；alpha `(1−t/29)^1.5` |
| ③ | **表面发光** | 音符盒本身亮一下（跟着①同一条 t 曲线，不额外加光斑） | 同①命令里的 `light=1` + 前 4 刻的 size 脉冲 | 与①共用 alpha；`light` 恒 1 |
| ④ | **火花** | 照搬烟花的散粒：随机方向、轻微重力、1.3s 淡出 | `custom-normal`（`attr` 里给随机初速/重力） | 初速 `v=0.1~0.4`，`gravity=0.06`，生命 26 刻 |
| ⑤ | 水面倒影 | 甲板下方一抹同色倒影（**只有近处的音做**，避免脏） | 同①的一个附加点（y<0 镜像） | 与①同 alpha × 0.35 |

> 剂量按**力度**取值：力度 75 以下只有 ①②③；90 以上加 ④；100 以上把颜色往血朱推 15%。
> 低音（bass 声部）只做 ①②③ 且半径 +20%（低频要"沉"不要"炸"）。

### 4.2 河（底层，全曲常驻）

一条**恒速光流**：`tick-parameter` 每刻发射 5 颗、参数步进 0.0833 格/颗 →
前沿速度 = 5 × 0.0833 = **0.4167 格/刻**，与播放头**逐格相同**（这就是为什么它永远不飘）。
三条河线（z = 河心 ±1.2 / 岸边）+ 一层薄雾（1.5 格高、低 alpha、慢摆）。
安静段 alpha ×0.3（暗流），副歌 ×1.0（发光的河）。

### 4.3 光幕（"现在线"）

播放头处一片竖直光幕（高 7 格、宽覆盖 25 行音位），亮度跟段落等级；
底部甲板处一颗亮核。**它是全片的视觉节拍器**：观众的注意力被训练到"光幕推到哪里，音乐就到哪里"。

### 4.4 螺旋（Helix，副歌/高潮）

两条反向缠绕的光带绕机器轴（y≈6.5、z=2.5）推进，半径随段落收紧/放松
（主歌 8 格 → 副歌 5 格）；推进速度 = 播放头速度，转向相位 = 2 圈/8 拍（约 2s 一圈，肉眼可读）。
段落切换时 **`group remove helix` → 重新开一条**，这就是"每个乐句加一圈"的实现方式。

### 4.5 冲击环（重音，141 个）

由**真实重音**（力度算出的 141 个点）驱动：每个重音在播放头处横向铺开一个甲板环，
半径 0.6→13 格、0.8s、alpha 平方衰减。**它不是节拍器，是"鼓点被看见"**——
预演片进度条上的那些小刻度就是它的来源，可以直接对拍。

### 4.6 空环（2:45.21）

在播放头处**描**一个竖立的空环（半径 13.5 格）：2.4s 从 12 点方向顺时针描完，
停 0.6s，再用 2.6s 散开消失。这一条完全为那句歌词服务。

### 4.7 两段"反向"段落（专用）

| 段落 | 时间 | 做法 |

| **记忆之砂** | 1:34.8–1:56.4 | 镜头**逆流**看已弹过的河；已弹方块的余温被拉长（3.2s）+ 从上方落下的细砂 |

### 4.8 逐字歌词（参考 AMLL 播放器；取代 2026-09-20 的"歌词只在剪辑里做"）

参考实现在 `C:\Users\hiliang\Documents\amll\amll-player`（AMLL，模仿 Apple Music）。
**从它的源码里读到的口径**（不是印象）：每个 word 都有自己的 `setTransform(scale, opacity, blur)`，
每行有 `setTransform(left, top, blur)`；所有量都走 **Spring**（`SpringParams`：`posX/posY/scale/blur` 各一根弹簧）；
行级模糊上限 **5px**（`filter:blur(min(5,blur)px)`）。逐字时间用**母版映射版**：
`nbaurora/lyrics/styx_helix.final.master.json`（61 行，逐字 `chars[].s/e` + 中文翻译 + 罗马音；
源 TTML 是 `…\STYX HELIX - EP\1-01 Styx Helix.ttml`，但它的时间轴是 EP 版，比钢琴母版早 ~3.1s，不能直接用）。

| AMLL 效果 | 粒子实现（MC 没有 blur，用「点尺寸 + 透明度」近似） | 表达式口径 |
|---|---|---|
| 逐字填充（mask） | 唱到哪亮到哪 | `alpha=0.34+0.66*clamp((t-t0)/dur,0,1)`；颜色 `mix(冥河青×0.45, 苍白白, p)` |
| 弹性缩放（spring） | 字刚亮起时放大再回落 | `size × (1 + 0.22·e^(−(t−t0)/3))`（3 刻 ≈ 0.15s 时间常数） |
| 模糊（blur） | 未唱的字更小更淡；上一行更小更淡并上移 | 未唱 `size×0.75 / alpha×0.5`；上一行 `size×0.72 / alpha×0.5 / Δy+1.5` |
| 行进出 | 整行滑入 + 淡出 | 进场 0.35s、出场 0.6s |
| 浮动（float） | 每字轻微上下摆 | `y += 0.07·sin(t·1.15 + i·1.7)` |

**「骑流」是这个设计的核心技巧**：歌词不重挂、不追播放头——给每颗粒子的每刻表达式写 `vx = 0.4167`
（= 播放头速度，§2 的恒速公式），**整行字像船一样骑在河上**，与音乐永不失步。
字放在 y-z 平面（法线沿 ±x），顺流机位看过去正好是正面。

> **2026-09-24 数据换基座**：逐字时间改为直接取**官方 TTML 的 `<span>`**（`1-01 Styx Helix.ttml`，EP 时间轴），
> 只做整体平移对齐到钢琴母版，不再用"按モーラ/音节重算"的那一版（用户：之前那份逐字是错的）。
> 平移量先取逐行 Δ 的中位数（+2.567s）；但逐行 Δ 实际在 **+0.87 ~ +4.97s** 之间跳、线性拟合残差 rms 1.44s ——
> 也就是**改编确实改了长度**（母版 298.7s vs EP 291.2s），所以现场用 `/nbm machine lyricoff <秒>` 微调。

* 每字一条 `text` 命令（`text` 支持 `expression` 逐像素给属性 + `speedExpression` 逐刻给运动），
  存活 = 该行时长 + 0.6s 淡出 → **全曲 ≈ 620 条命令**；
* 分层不变：**游戏内粒子字 = 视觉元素**（随河漂、唱到哪亮到哪）；**可读字幕仍留在剪辑层**。

## 5. 颜色与强度映射

5 支颜色（`show/styx_helix.show.json` 的 `palette`）：

| 名字 | 值 | 用途 | 出现位置 |
|---|---|---|---|

| 螺旋紫 | `#7860FF` | 螺旋、低音声部、桥段的"巫女雾" | 副歌 / 2:50–3:20 |
| 苍白白 | `#E6F2FF` | 旋律、光幕、棱边、空环 | 全曲 |

| 暖金 | `#FFC987` | 尾段"新的一天"之后的世界 | 4:03 起 |

映射规则：

* **声部 → 基色**：harp = 苍白白（高音更白、中音偏青）；bass = 螺旋紫。
* **力度 → 亮度**：`alpha × (0.55 + 0.45·vel/110)`，不允许整块变白。
* **音高 → 色相微抖**：在青↔紫之间最多 15% 偏移，**不做彩虹**。
* **段落等级 → 剂量**：`dynamics-sections.json` 的 level（0.06–0.92）× 局部音密度 →
  0–4 级。弱段不许超过 1 级（安静段不吵），强段不许全 4 级（高潮不过曝）。

### 7.3 两个必须记住的刻率事实

* **粒子动画跑在客户端 20 tps**：ExParticle 的每刻表达式走客户端 tick（`ParticleGroup.tickParticle`），
  `/tick rate 100` **不会**让粒子动 5 倍快。→ 所有曲线按 1/20s 设计；`t` 就是"过了几刻"。
* `/tick rate 100` 买到的是**触发时刻的精度**（±5ms 而不是 ±25ms），也就是"光幕和钢琴是不是同一瞬间"。
  这是全片同步感的来源，**录制前必须开**。

### 7.4 出片（沿用现有链路，只多一个风险点）

录制（Flashback）→ 后期加相机 keyframe → 导出（可挂无损音轨）→ `mux-video.mjs`。
**唯一风险**：Flashback 回放是否**重放自定义 payload**（ExParticle 的粒子就是靠它下发的）。
如果重放 → 后期渲染能看到全部粒子；如果不重放 → 退回 OBS 直录（机位在录的时候定死），
或者只把"河/螺旋"这类**长寿命**元素改成由回放重跑。**这一条是实现前第一个要做的实验**（见 §9-4）。

**拍摄前的必做项（2026-09-24 核对后新增）**：`/nbm machine start` 用的是**滚动强加载**
（当前音 ~ 未来 40s ≈ 前方 333 格；后方只留 ~6 chunk ≈ 96 格、约 11 秒）。
所以：

* **河面/高扫镜头**（跟着播放头走）没问题；
* **逆流镜头**（S4 记忆之砂、S8 尾退潮、S9 尾奏）会看到"十几秒之前的机器已经不在场"；
* 修法（按成本从低到高）：① 拍摄前手动 `/forceload add` 整台（三段，和 `redo` 同窗口），并**别让 mod 在结尾释放**（`releaseForceload` 只释放它自己登记过的 chunk，重叠的手动强加载会被它 `setChunkForced(false)` 清掉 → 要么每 10 秒重申一次，要么给 mod 加一个 `capture` 开关把窗口放到整台常驻）；② 只在 `FORCELOAD` 覆盖范围内取景。
  建议做 ① 的 `capture` 开关（约 10 行）：拍摄期整台常驻、`stop` 时统一释放。

## 8. 命令样例（按移植版实测语法写，可直接在游戏里跑）

参数口径（源码核对，非猜测）：

* `size` 的单位是 **1/8 格**：`size=8` = 1.0 格宽（`IParticle.setCustomSize` 里 `× 0.125`）。
* `age` 单位是**刻**；`age=-1` = 永不消失。`light=1` = 强制全亮（发光粒子的关键）。
* 每刻表达式里的 `t` = 已过刻数（`step` 每次累加，默认 1.0）；`dx/dy/dz` = **相对中心的初始偏移**，
  这是"从方块大小等比例放大"能一句话写出来的原因。
* 生成器参数顺序：`<粒子> <坐标> <颜色 r,g,b,a> <初速 x,y,z> <begin> <end> <表达式> [<step> <cpt> <age> [<每刻表达式> <速度步长> <组名>]]]`；
  `custom-*` 把"颜色"换成 `attr`（逐粒子属性表达式）。
* ⚠ **`color4` / `speed3` / `range3` 是空格分隔**（源码 examples：`"0 0 0 1"` / `"0 0 0"` / `"1 1 0"`），写成 `0,0,0` 会被 Brigadier 拒掉；
  **表达式内部的元组仍然是逗号**（`cr,cg,cb=1,1,1`，`(vx,vy,vz)=…`）。
  这条是 2026-09-24 实测踩出来的：整套命令被**静默**拒掉（source 是 silent，`parseAndExecute` 把错误吞了），
  日志里显示"失败 0 条"却一个粒子都没有。现在 `StyxShow.exec()` 改成**先 `dispatcher.parse` 再 `execute`**，
  并加了 `/nbm machine showcheck` 一键自检（把每一类模板各拿一条真去解析，失败就打印原文与原因）。

```mcfunction
# ① 描边方块：12 棱 44 点（体素格 0.25，只留棱）= 一条命令
#    等比放大 (vx,vy,vz)=(dx,dy,dz)*k/(1+t/8)；同一条曲线淡出
particlex custom-conditional end_rod ~ ~ ~ "size=6; cr,cg,cb,alpha=0.90,0.94,1.0,1.0; age=28; light=1.0" 0.5 0.5 0.5 "abs(abs(x)-0.5)<0.01&abs(abs(y)-0.5)<0.01|abs(abs(x)-0.5)<0.01&abs(abs(z)-0.5)<0.01|abs(abs(y)-0.5)<0.01&abs(abs(z)-0.5)<0.01" 0.25 "(vx,vy,vz)=(dx,dy,dz)*0.11/(1+t/9); alpha=1-t/27" 1.0 nb_flare

# ② 表面涟漪：水平单环（s2=0），半径由 dis 给、方向由 dx/dz 决定 → 天然"连贯"
particlex custom-polar-parameter end_rod ~ ~ ~ 0 6.2832 "s1=t; s2=0; dis=0.5; size=5; cr,cg,cb=0.15,0.86,0.80; alpha=0.9; age=30; light=1.0" 0.1 "(vx,vy,vz)=(dx,dy,dz)*0.12/(1+t/10); alpha=0.9*(1-t/29)" 1.0 nb_ripple

# ③ 火花：照搬烟花口径（随机方向 + 轻重力 + 摩擦）
particlex custom-normal end_rod ~ ~ ~ "size=2.5; cr,cg,cb=0.92,0.96,1.0; alpha=0.95; age=26; light=1.0; vx=(random()-0.5)*0.16; vy=random()*0.22; vz=(random()-0.5)*0.16; gravity=0.06; friction=0.96" 0.15 0.15 0.15 14

# ④ 河：恒速光流。前沿速度 = cpt × step = 5 × 0.0833 = 0.4167 格/刻 = 播放头速度（同一条河永不飘）
particlex tick-parameter end_rod -40 110.1 2.5 0.15 0.86 0.80 0.28 0 0 0 0 2400 "x,y,z=t,0.1*sin(t/4),sin(t/9)*1.2" 0.0833 5 26

# ⑤ 螺旋：一条反向缠绕的光带（相位差 π 的另一条换 dis/s1 的符号即可）
particlex tick-polar-parameter end_rod -40 116.5 2.5 0.47 0.36 1.0 0.5 0 0 0 0 2400 "s1=t*0.62; s2=1.5708; dis=6" 0.12 3 40

# ⑥ 段落切换：收掉旧螺旋、清掉脏粒子
particlex group remove helix
particlex clear-particle
```

> 上面 ⑥ 的 `clear-particle` 只在**重置节点**用（1:20.47 / 2:34.54 / 3:36.95），
> 平常段落切换只 `group remove helix`，不打断正在扩散的心跳。

## §10 开场三件套 v3：一图一四边形（2026-09-24）

用户口径（2026-09-24，两轮录屏）：**"封面图不全"**、**"清晰度能不能做到跟原图一致"**。

### 10.1 为什么点阵做不到

旧版把封面渲染成"一像素一颗粒子"的点阵（192² = 3.7 万颗 `end_rod`）。实测结论：

| 现象 | 取证 | 结论 |
|---|---|---|
| 暗部看不见、像"封面不全" | 用户 4K 录屏 1:1 裁切：矩形中下方能看到**水纹透过封面** | `end_rod` 精灵是软光点，暗像素 × 软 alpha ≈ 透明 |
| 内容糊、小字认不出 | 同上；192px/dpb24 + size 2.2（0.275 格 = **6.6 倍点距**）| 叠这么多才铺满，必然糊；清晰度被精灵尺寸卡死 |
| 改硬边方片也救不了 | `minecraft:block` + `size` 恰好铺满点距（dpb=2/3、size=4/2.8）实机截图 | 粒子位置有抖动，1× 铺满时画面变**彩纸屑**；只有大面积重叠才"看起来完整"，那就回到糊 |
| 分辨率上限 | 一像素一颗粒子，192² 已 3.7 万颗 | dpb 再翻倍 = 15 万颗，不划算 |

**结论：清晰度问题不是参数没调好，是"粒子 = 一个点"这个模型的天花板。**

### 10.2 现在的做法

**一张贴图 = 一颗 `minecraft:block` 粒子**，quad 是 billboard（自动正对镜头），
所以：清晰度 = 贴图分辨率（封面 2048²），完整度 = 贴图本身（不透明像素全都画），
粒子数从 3.7 万降到 **3 颗**，动效（淡入/淡出/漂移/微放大）走 ExParticle 的 alpha/size/vx 表达式。

贴图必须挂在**模型里显式写了 `particle` 槽**的方块上（否则覆盖贴图无效——实测
`structure_block` 的 `cube_all` 没有 particle 槽，覆盖 `block/structure_block_save` 后粒子仍用原版贴图）。
选的都是"正常世界里不会出现"的方块：

| 元素 | 粒子方块 | 被覆盖的贴图 | 尺寸 |
|---|---|---|---|
| 封面 | `minecraft:jigsaw` | `block/jigsaw_top` | 2048²（源图 1424²，lanczos + unsharp） |
| 标题 | `minecraft:bamboo_fence_gate` | `block/bamboo_fence_gate_particle` | 1024²，白字居中、四周透明 |
| 副标题 | `minecraft:conduit` | `block/conduit` | 1024²，同上 |

命令形态（`styx-1px.png` = 1×1 白点，粒子颜色 = 白 × 贴图 = 贴图原色）：

```
particlex image-matrix minecraft:block{block_state:"minecraft:jigsaw"} <x> <y> <z> \
  styx-1px.png 1.0 "E4" 1 0 0 0 110 "size=64*(1+0.06*clamp((t-1.9)/1.3,0,1)); light=1.0; alpha=…; vx=…; vz=…" 1.0
```

`size` 单位是 **1/8 格**：8 格见方 → `size=64`。

### 10.3 配套改动（都要一起装）

1. **exparticle-fabric**：新增 `TerrainParticleMixin` —— 被 ExParticle 的 `size` 表达式接管过
   （`getCustomSize()` 非 NaN）的 `minecraft:block` 粒子改画**整张 sprite**；
   原版只随机取 sprite 的 1/4×1/4 子块（那是给"方块碎裂"用的）。
   ⚠ `sprite` 字段声明在 `SingleQuadParticle` 上、被 `TerrainParticle` 继承，
   直接 `@Shadow` 会崩在启动（`field_62632 was not located in the target class`），
   所以走 `SpriteAccessor` 接口（`SingleQuadParticleMixin` 实现）。
2. **资源包 `styx-plates`**：由 `tools/render-plate-pack.mjs` 生成到
   `<gameDir>/resourcepacks/styx-plates/`，并在 `options.txt` 的 `resourcePacks` 末尾加
   `"file/styx-plates"`。**含专辑封面，产物不进 git**（仓库里只放生成脚本）。
   1.21.10 的 `pack.mcmeta` 必须是 `{pack_format:69, min_format:69, max_format:81}`：
   只写 `pack_format` 会被判"声明了比 64 新的版本却缺 min/max_format"直接拒绝加载。

### 10.4 已知坑

* 一图一四边形后**丢掉了"按行逐像素吹散"**：单颗粒子做不了逐像素，改成整体漂移 + 淡出 + 1.06× 微放大。
* 会话级卡死：长时间反复 spawn + `F3+T` 资源热重载之后，出现过**所有 image 粒子都不再渲染**
  （命令仍被正常接收、聊天栏无报错）；重启游戏即恢复。用户正常流程（重启 → `/nbm machine start`）不受影响，
  但**别把 F3+T 当作改贴图的常规手段**——改贴图就重启。
* `light=1.0` 对 `minecraft:block` 粒子目前**不生效**（`TerrainParticle` 覆写了 `getLightColor`，
  遮蔽了 `ParticleMixin` 的自定义亮度）。雨天/夜间画面里板子会跟着世界光变暗。
  要修就照 `SimpleAnimatedParticleMixin` 的样子，在 `TerrainParticleMixin` 里
  `cir.setReturnValue(super.getLightColor(partialTick))`。

## §11 开场 v4：屏幕锁定 + 点阵消散（0.6.0，2026-09-24）

用户三条反馈（原话）：**"清晰封面图还是在做移动"、"点阵消散没做好、有乱的方块"、"点阵不像图，像个球"**。
三条其实是同一批根因，逐个查实后这么改：

### 11.1 根因（都有实机取证）

1. **"还在动"** = 世界坐标固定 + 相机在飞。板子钉在世界里，镜头一往前飞就把它甩出画面/放大。
   录屏取证（`2026-09-24 12-21-54.mkv`）：封面从画面中心滑到左边缘再缩小。
2. **"像球"** = 点太大。上一版 64² 点阵配 `size=12`（当时以为 1.5 格），实际屏幕上一个点
   盖住十几个点距，整张图糊成一团。
3. **"有乱的方块"** = 上面两条的合成：一团大点 + 镜头飞过去，看起来就是一群方块乱飞。
4. **顺带查出的大坑**：表达式里的 `t` 是**刻数**（命令末尾 `step=1` 时每刻 +1），
   而 0.5.1 把"秒"直接写进去（`clamp(t/0.45,…)`）→ 淡入只花 0.45 刻 ≈ 一帧。
   用户那句"闪一下就没了"就是这么来的。**秒必须 ×20**。

### 11.2 做法：把整组钉在屏幕上

* ExParticle 侧新增**镜头参照变量**（`CameraRef`，每客户端刻刷新一次）：
  `px/py/pz` 眼位、`fx/fz` 水平前、`rx/rz` 水平右、`yaw` 弧度。
* 三件套（封面/标题/副标题）每刻把自己**挪到「眼位 + 前×13.5 + 上×v」**：
  `vx=(px+fx*13.5)-(cx+x); vy=(py+v)-(cy+y); vz=(pz+fz*13.5)-(cz+z)`
  （写"目标 − 当前"而不是增量 → 自纠偏、不漂移）。
* 封面点阵（128²，`dpb=8` → 16 格）用同一套公式，多一项按发射时的相机右向换算的平面内偏移：
  `+rx*(r0x*dx+r0z*dz)`（水平）与 `+dy`（竖直）→ 镜头转身时整片点阵跟着转。
* 点阵**全程不透明**，靠"清晰板淡出把它露出来"做交叉过渡（半透明叠色在光影下会变麻点），
  之后从画面中心向外逐层淡出：`alpha=1-clamp((t-15-ddis*1)/11,0,1)`。

### 11.3 几何标定（别再猜了）

同一帧里放两把尺子实测（`_scratch-m3-39/gpu` 的 `measure-bright.mjs` / `_bbox*.mjs` 那一套）：

* 6 格外放 1×1 红石块 → 101px/格；据此换算 13.5 格外 **1 格 ≈ 45px**（1600×900 全屏截图）。
* `size=64` 的清晰板在 13.5 格外量得 **671px ≈ 15 格** → **渲染出来的四边形 ≈ size/4 格**
  （1.21.10 的 `SingleQuadParticle` 把 `getQuadSize()` 当**半边长**用，所以是两倍）。
  旧文档里"size=64 → 8 格"是错的（当时只按 1/8 格推，没量过）。
* 点阵那侧是 `像素/dpb` 格，**没有这个 2 倍**：128px ÷ dpb8 = 16 格，与板子对齐。
* 结论写进代码常量：`PLATE_BLOCKS=16`、`PLATE_SIZE=64`、`COVER_DPB=128/PLATE_BLOCKS=8`、
  点尺寸 `0.25+0.45*L`（点距 16格/128 = 0.125 格，size 0.5 时点正好相接）。

### 11.4 时间线（秒）

```
0.00/0.10/0.15  清晰板淡入 0.45s
2.30            封面点阵在清晰板后面 0.35 格不透明就位（16384 颗）
2.35/2.45/2.50  清晰板淡出 0.70s → 露出点阵（交叉过渡）
3.05→3.88       点阵从中心向外逐层淡出（消散）
3.917           第一颗音
```

### 11.5 验证（0.6.0 实机）

* 录屏 `_scratch-m3-39/gpu/show_b.mp4`（gdigrab 抓窗口 14s，期间按住 W 前飞 4s ≈ 10 格/秒）。
* 清晰板边缘逐帧量取：**1.6 秒内左边缘恒为 786px、右边缘恒为 1146px**（±1px）→ 屏幕锁定成立，
  没有抖动/呼吸；交叉过渡帧里点阵与板子边界对齐；消散是从中心向外淡出。
* 采样脚本与证据留在 `_scratch-m3-39/gpu/`（`_edge.mjs`、`t_xfade.jpg` 等），不进仓库。

## §12 开场 v5：钉在世界里 + 封面/文案并排（0.7.0，2026-09-24）

### 12.1 "卡卡的"根因与修法

| 现象 | 取证 | 修法 |
|---|---|---|
| 交叉过渡附近连掉 3 帧 | 30fps 抓窗口录屏逐帧差分：0.6.0 在 3.00/3.27/3.43s 各有一帧完全静止（≈33–66ms 卡顿），而那段正好是 **16384 颗点阵一次性 spawn** | 把点阵切成 **12 条 × 8 行**（每条 768 颗，`styx-dot-b00..b11.png`，条带外 alpha=0），0.60–1.20s 每刻铺一条 → 每刻只 +768 颗 |

## §13 开场 v5.1：屏幕锚定、只显现/消失（0.7.1，2026-09-24）

用户追评："效果还是不错的，但是我还是不太需要让他们移动，只需要自然显现和消失就可以了。"
——0.7.0 的"世界固定"在飞行时会被推近放大（观感就是"在动"），0.6.0 的"视角锁定"又会跟着转头甩。
0.7.1 取中间解：

* **屏幕锚定**：表达式每刻把卡片搬到「当前眼位 + **起播方向**×16 格 + **起播右向**×版面偏移」
  （`anchorTo` / `anchorCloud`）。方向用起播那一刻的**常量** `fx/fz/rx/rz`（不是实时视角），
  所以飞行时卡片跟着平移 → **屏幕上位置与大小完全不变**，只有淡入/淡出；
  转头时它会自然滑出画面，不会"甩着跟着转"。
* 开关 `OPEN_SCREEN_ANCHOR = true`（关掉即回到 0.7.0 的纯世界固定），方便以后再换。
* 只用到 ExParticle 的只读眼位 `px/py/pz`（每刻刷新）；点阵的每颗点再叠加引擎给的 `dx/dy/dz`
  在画面平面内的投影，竖直项直接用 `dy`。

实机复测（抓窗口录屏 + 逐帧量边缘，镜头 10 格/秒前飞 4 秒）：
封面左边缘 1.8s→2.6s 只从 **623px 漂到 619px**（<0.3%），可认为屏幕上完全静止。

## §14 开场 v5.2：点阵对位、文字同步淡出、文字轮廓（0.7.2，2026-09-24）

用户三条（附游戏内截图）："点阵有一小部分遮盖掉了封面"、"文字的消失动画还比较生硬，而且没有做到和封面同步"、
"文字可以加阴影，也可以上轮廓线，可能轮廓线的方式更好"。

1. **点阵偏右盖到文案** —— `anchorCloud` 少加了版面水平基准：点阵每颗点的目标位置只算了
   `起播右向 × 点内偏移`，没有加上封面那一档 `OPEN_COVER_H = −6.5` 格，于是整片点阵相对封面
   **右偏 6.5 格**，正好压在文案上（用户截图取证）。修法：`anchorCloud(dist, hBase, …)` 把
   `hBase = OPEN_COVER_H` 加进 x/z 两项 → 点阵与封面同轴，仅靠 0.35 格前后差做遮挡。
2. **文字与封面不同步 / 生硬** —— 原先把文案的淡出排在封面之后（2.60→3.35s，为的是"多读一会儿"），

   点阵消散顺延到 3.10s 起（0.55s + 0.025s/格半径错开 → 3.86s 收完，仍早于第一颗音 3.917s）。

3. **文字轮廓** —— 描边从 2px/0.55 提到 **5px/0.85 实黑**（外加 2/3px 投影），亮天空与白云下也清晰；
   1024² 贴图里 124px 的曲名，5px 轮廓约等于字高的 4%，不会糊。

## §16 开场 v6：点阵原地打印 → 清板压上 → 一起缩没（0.7.4，2026-09-24）

用户四条反馈：①封面最后左右抖动；②打印改成"左上角 → 右下角"；③点阵要和封面文字**同时**消失；
④打点时"好像连成一个图像了"并闪动。

### 16.1 三条实机结论（先做 A/B，再改设计）

一次开光影（iterationRP Alpha 0.8.26）的对照实验打 `alpha` 的底（同一张 `minecraft:jigsaw` 封面板，
三等分摆在 16 格外，唯一差别是 `alpha`）：

| alpha | 观感 |
|---|---|
| 1.0 | 完整封面，暗部（深蓝底）**正常显示** |
| 0.55 | 暗部**整块消失**，只剩手臂/花/白字浮在天空上（像加色发光，不是普通半透明） |
| 0.30 | 同上，更淡 |

也就是说：开光影时这块板子**一旦 alpha<1，暗部就先没了**。所以"封面最后"那一段看起来像换了一张图、
或者像抖了一下——不是位置在动（逐帧量左边缘 ±0.3px 稳如磐石），而是**画面内容**在中途换了。
`end_rod` 点阵同理（alpha 0.5 的对照点阵整片发白）。→ 结论：**淡出/消散一律不能靠 alpha，只能用几何
（size）**；开场里保留 alpha 的只剩文案块（白字+描边，fade 时是"亮字渐隐"，没有暗部丢失问题）。

另外两条（都是这次实机量到的）：

* **单个表达式里两个 clamp 相乘 → 整颗粒子不渲染**：同一张点阵图、同一位置，`clamp(...)` 正常出图，
  `clamp(...)*clamp(...)` 一颗都不出。所以"长出来"和"缩回去"必须拆成两批粒子，各带一个 clamp。
* **同屏粒子上限约 16384**：一次摆 4 张 96² 点阵（≈3.7 万颗）时，`jcmd GC.class_histogram` 里
  `ParticleStruct` 只活下来 **16098** 颗，后面的整批被引擎丢掉。

### 16.2 抖动（①）的真因与修法

0.7.3 的点阵层相对封面**右移 6.5 格**（`OPEN_DOT_SHIFT_H`）。同一张图因此有两份错位副本：
封面暗部一消失（见 16.1），眼睛看到的就是"同一张画在两个位置之间跳"，即用户说的**左右抖动**。

修法：`OPEN_DOT_SHIFT_H = 0` —— 点阵与封面**同轴重合**（仍靠 `OPEN_DOT_BACK = 0.35` 格排在后层）。
同轴之后：打印就是"这张图自己长出来"，淡出就是"清晰封面原地化回点阵、点阵再缩没"，全程只有一个图像。

### 16.3 打印顺序（②）与"连成一个图像"（④）

* `tools/render-dot-bands.mjs` 新增 `--mode diagonal`：把 96² 素材按 **X+Y 等面积**切成 12 条**斜带**
  （角上密、中间稀 → 每带像素数都在 780–1000 之间，扫描时墨水流量均匀）。第 0 条只含左上角、
  第 11 条只含右下角 → 打印顺序天然是"从左上角推到右下角"。
* 每颗点按**自己的对角坐标**错开长出来：`size = S · clamp((t + t0 − k·D)/rise, 0, 1)`，
  其中 `D = (dx·rx + dz·rz) − dy + 12 ∈ [0,24]`（画面左上到右下的对角坐标，推导见 `dotDiag`）。
  于是整片点阵是**逐颗**连续长出来的，而不是"一条带整块跳出来"——这就是 0.7.3 里"打点像在闪"的来源。
* 点尺寸从 0.25–0.70 收到 **0.32–0.48**（四边形 0.08–0.12 格，**恒小于点距 0.125 格**），
  任何亮度下都留缝：不会再糊成一整片实心图。

### 16.4 一起消失（③）与两拨点阵

单个表达式塞不下"长出来 + 缩回去"（16.1 的 clamp 限制），所以点阵分两拨：

```
0.00→0.60  第一拨点阵：12 条斜带分批生成，逐颗按对角坐标长出来（打印）
0.60→1.20  点阵定格（看清）
1.20→1.90  封面淡入（压在点阵上）；1.25→1.95 文案淡入
2.00       第一拨点阵整批到期（此时被不透明封面完全挡住，看不到闪）
2.60→3.40  封面 + 文案淡出；同时第二拨点阵（同轴同图）按同一对角顺序缩到 0
3.917      第一颗音
```

实测（抓窗口录 30fps，逐帧看）：3.40s 后画面只剩机器本体，没有残留点阵；封面阶段肉眼可见
"点阵 → 清晰封面"的收紧过程，结束阶段是"封面 → 点阵 → 缩没"一条线走完。

### 16.5 调试开关

`-Dstyx.nodots=true`（只放封面/文案）、`-Dstyx.noplates=true`（只放点阵）——这次靠它把"抖动/连片"
的元凶在两次启动内定位到点阵层，以后拆这类问题直接用。

## §17 开场 v7：右偏点阵 + 出生点现算 + 拆块溶解（0.7.5，2026-09-24）

用户第二轮意见（附截图）：①点阵要**右偏**才对；②封面+文字**同时出现** → 点阵再打点 → 封面+文字**同时消失** → 点阵**随之**自然消失；③封面最后**左右抖动依旧**（我的截图没截到）；④圈出的位置就是"打点时闪烁"；⑤封面/文字的消失动画**不自然/不灵动**。

### 17.1 抖动/闪烁的真因：新粒子的**出生点用了旧机位**（关键）

开场卡片走的是"屏幕锚定"表达式：每刻把粒子搬到 `眼位 + 起播方向×16 + 起播右向×版面偏移`。
但粒子**被创建的那一帧**并不在锚定目标上——它落在命令给的世界坐标（= 起播那一刻算出来的位置），
要到**下一刻**才被搬到当前机位对应的位置；而渲染位置是 `lerp(上一刻位置, 当前位置, partialTick)`，
于是每颗粒子出生的那一两帧会**先闪在旧机位**、再归位：

* 封面板：退场那一颗是 2.30s 出生的新粒子 → 播放时人已经飞出去十几格 → "封面最后左右抖动"；
* 点阵：12 条斜带是 0.75→1.19s 逐条出生的 → 每条都闪一下旧位置 → "打点时闪烁"（用户圈的深色斜条 + 竖线就是这些错位副本叠出来的）。

**修法**：开场队列改成 **到点才拼命令**（`Pending` 存 `Supplier<String>`），出生点用
`anchorPoint(world, dist, h, v)` 按**当前眼位**现算。锚定表达式不变，两处坐标从此自洽。

实机取证（0.7.5，全程按住 W 全速前飞，抓窗口 30fps）：
**封面左边缘 1.13s→2.73s 恒为 371px**（逐帧 0 像素抖动），退出阶段只单调右移（拆块在退）。
改前同机位测到 5–13px 的 20Hz 抖动 / 逐条闪点。

### 17.2 时间线（用户口径逐条对齐）

```
0.00→0.70  封面 + 文案**同时**淡入（同一时刻起）
0.75→1.45  点阵打点：12 条斜带分批生成，每颗点按自己的对角坐标**逐颗长出**（左上 → 右下）
           ——点阵整体比封面**右偏 6.5 格**、后 0.35 格（OPEN_DOT_SHIFT_H 恢复 6.5）
1.45→2.28  定格（点阵只在封面右侧露出来）
2.28       封面/文案的 16 块"拆块板"整体接上（同图同位，交接无缝）
2.30→3.07  4×4 块按对角顺序逐块缩没（每块 delay 后 0.25s 缩到 0，全程 alpha=1）
3.10→3.86  点阵**在封面/文案消失之后**才逐颗缩没（同一对角顺序，"随之自然消失"）
3.917      第一颗音
```

实测（同样全速飞行）：2.77s 起左边缘 371→372→375→388（单调 = 块在退），2.93s 左半区已清空；
3.2s 时点阵暗像素从 4.0 万降到 6.4 千 → 点阵确实是在封面之后才收。

### 17.3 拆块溶解：给 ExParticle 加了 sprite 取景窗（u0/u1/v0/v1）

发暗板子用 alpha 淡出在开光影下会把暗部整块吃掉（§16.1），所以退场改成**几何**：
把封面/文案各切成 **4×4 块**，每块一颗粒子、全程 `alpha=1`，只把 `size` 缩到 0。

为此在 `exparticle-fabric` 侧新增（对应 `1.5.2-fabric.3`）：

* `ParticleStruct` 加 `u0/u1/v0/v1`（默认 0,1,0,1）——表达式引擎按**公有字段反射**建变量表，写进表达式即可用；
* `IParticle` / `ParticleMixin` 存取这组值（逐刻由表达式刷新）；
* `TerrainParticleMixin` 的 UV 覆写改成"整张 sprite 的哪个子矩形"：`sprite.getU(u0)…getV(v1)`。

隔离验证（`/nbm machine showcheck` 之外的现场单发）：单发 3 块（左上角 / 正中 / 右下角）落在
12 格版面的预期位置、内容各自正确、块边相邻（≈3 格间距 vs 3 格边长）→ 16 块能拼回整张图。

### 17.4 还没做的（用户没提，留作备选）

* 入场仍是 alpha 淡入（暗部会晚一点显形，但用户只吐槽了**消失**）。拆块机制已经就位，
  想换成"从左上角逐块长出来"只需把 `tilePlate` 的 shrink 换成 grow。
* `-Dstyx.nodots / -Dstyx.noplates` 两个诊断开关保留。

## §18 开场 v8：取消打点、出现/消失统一成同一种拆块动画、封面与文案速度对齐（0.7.7，2026-09-24）

用户三条：①"消失动画用和出现动画一样类型的吧"；②"不用点阵打点了"；③"封面和文字的出现动画时长(速度)不太一致，优化一下"。

### 18.1 先量了"速度不一致"到底差在哪

把封面板/文案板**各自单发**（同一条 `alpha=clamp(t/14,0,1)`、同机位、同 0.7s），逐帧看：

* 文案（白字+黑描边）**0.6s 就看清了**；
* 封面（深色专辑图）到 **1.0s 才成形**——中间一直是"只剩亮部的一层虚影"。

原因是 §16.1 那条：开光影时 alpha&lt;1 的板子**暗部整块消失**（加色/去暗），所以"同一段淡入"里，
深色封面看起来比白字**晚 0.4s 才出现**。也就是说：只要还用 alpha，封面与文案的**观感速度永远对不齐**。

### 18.2 结论：出现/消失都改成**同一种几何拆块动画**（4×4、对角顺序）

* **出现**：16 块 size 0→满；**消失**：16 块 size 满→0。同一套栅格、同一顺序（左上先）、
  同一段错开（0.04s/步）、同一时长（每块 0.35s）。→ ①"同类型" ✓、③"封面与文案同速度" ✓
  （几何动画对深色封面与白字完全一视同仁，且不受光影影响）。
* 每块只画自己那块贴图：靠 ExParticle 新增的 sprite 取景窗 `u0/u1/v0/v1`（见 §17.3）。
* 入场错开从 0.09s 收到 **0.04s**（远小于每块 0.35s 的时长）→ 16 块在时间上互相重叠，
  读起来是"整幅图连着填满/退掉"，不是孤立方块逐个蹦。

### 18.3 取消"点阵打点"（②）

12 条斜带不再逐点/逐带长出，改成**整片一起从 0 长到满**（0.75→1.35s，几何缩放、不碰 alpha），
消失时在封面/文案收完之后（3.00→3.70s）**整片缩回 0**。

时间线（0.7.7）：

```
0.00→0.59  封面 + 文案：同一套拆块动画长出来
0.75→1.35  点阵整片长出来（不再打点；仍比封面右偏 6.5 格、后 0.35 格）
2.28→2.87  封面 + 文案：同一套拆块动画缩回去（同类型、同顺序、同时长）
3.00→3.70  点阵整片缩回去（在封面/文案消失之后）
3.917      第一颗音
```

### 18.4 备选（用户想换随时说）

  代价是 §18.1 那条"深色封面比白字晚成形"会回来。

## §19 开场 v9：只留封面 + 文案、出现/消失都是柔和淡入淡出（0.7.8，2026-09-24）

用户最终口径：①"消失动画用出现动画一样类型的（**柔和淡入 淡出**）"；②"**把整个点阵去掉**"。

### 19.1 现在的开场只有两件事

```
0.00→0.35  封面柔和淡入（alpha = x(2-x)，x = clamp(t/0.35,0,1)）
0.00→0.70  文案柔和淡入（同一条曲线，时长 0.70s）
2.30→3.00  封面 + 文案**同时**柔和淡出（alpha = 1-x²，正是上面那条曲线的镜像）
3.917      第一颗音
```

* 曲线为什么是 `x(2-x)` 与 `1-x²`：两者互为镜像（`f(1-x)`），出现"起手快、收尾软"，
  消失"先稳住、末端收干净"；都只有一个 clamp + 四则运算，不会踩"两个 clamp 相乘整颗不渲染"的坑。
* **点阵层整层删除**：开场流程里不再发任何 `image-matrix end_rod` 点阵命令
  （`dot*` 模板与 `styx-dot-b*.png` 只在 `/nbm machine showcheck` 自检里还用得到）。
* 出现与消失都只用一颗粒子/板：淡入那颗活到退场时刻，退场那颗是"只淡出"的新粒子。

### 19.2 两块的时长为什么不一样（封面 0.35s / 文案 0.70s）

开光影时 alpha&lt;1 的板子**暗部整块消失**（§16.1），所以两块板子的"可见阈值"差很多：
白字文案 alpha≈0.25 就能读，深色封面要 alpha≈0.9 才算成形。实测（单发对照 + 逐帧看）：

| 方案 | 文案可读 | 封面成形 |
|---|---|---|
| 两块都用 0.70s 线性 | ≈0.20s | ≈0.80s（差 0.6s，用户报的"速度不一致"） |
| 两块都用 0.70s + 缓动 | ≈0.25s | ≈0.85s（更差：缓动让封面起手更慢） |
| **封面 0.35s + x(2-x) / 文案 0.70s**（现行） | ≈0.20s | ≈0.35s（基本同时到位） |

退场两块都用 0.70s：用户要"封面和文字同时消失"，同起同收最直观。

### 19.3 备选

* 想再柔一点：把两条时长一起放大（例如 0.6s / 1.2s），比例不变即可保持"同时到位"。
* 想回到几何动画（拆块/缩放）：`tilePlate` / `scalePlate` 两个模板都还在，替换 `opening()` 里的两处调用即可。

## §20 音符盒特效 v2（0.7.9，2026-09-24）

### 20.1 四条硬口径（都是实机取证，别再回退）

1. **一律不用 alpha 淡出，改用 size 收缩**：开光影（Iris + iterationRP）下 alpha<1 的粒子会被
   **dither** 成抖动噪点 —— 旧版 `glow.png`（16² 径向 alpha 渐变）+ 逐像素 alpha 在实机上是一块
   **发白的噪点方块**，`ring.png`（高斯环 alpha 峰值 150）是一条**麻点环**。这正是用户说的
   "柔光很拉跨 / 涟漪做不出来"。
2. **`ring.png` 改成不透明细环**（alpha 只有 0/255，半径 8.4–10.4px 的一条带，24px ÷ dpb15 = 1.6 格）：
   柔和度靠"环细 + end_rod 精灵本身软"，不再靠像素 alpha。生成器：
   `_scratch-m3-80/render-show-pngs.mjs` 第 4 段。
3. **锚点抬到方块顶面以上**：这台机器的水线就在音符盒顶面附近，以"方块中心"（y+0.5）为锚时
   整组特效有一半沉在水里 —— 从上方平飞看过去就是用户报的"特效在音符盒下方"。
   现在 `cy = y + 1.5`（顶面上方 0.5 格），描边框正好框住方块上沿，涟漪/柔光浮在水面之上。
4. **颜色要深、要饱和**：Iris 的泛光会把亮色核心洗成白，`sat 0.62 / val 0.75+` 的紫音在画面里
   就是一片白（用户："颜色过于单一"的真因之一）。现在 `sat 0.95–1.0 / val 0.42–0.62`，
   中心由泛光自己提亮，12 音级色环才立得住（C=红 … B=紫，低音声部整体偏紫）。

### 20.2 一颗音现在放什么（`noteFlare` → `fireNote`）

| 元素 | 做法 | 寿命 |
|---|---|---|
| 12 条棱（描边立方体） | `custom-conditional` 在 ±0.5 面上采样（step 0.05 正好命中 12 条棱），`(vx,vy,vz)=(dx,dy,dz)*0.035` 等比例扩散，size 0.6 收细 | 1.1s |
| 柔光 | 40 颗**不透明**小点（size 0.42）按半径衰减铺在 1.0 格半径内 —— 不再是半透明贴图 | 0.8s |
| 涟漪 | 不透明细环铺在顶面上方，半径按 `r ← r·(1 + 0.55/(1+t/3.5))` 先快后慢荡开；力度 ≥70 时叠第二圈（慢一拍、铺更远） | 1.2s / 1.8s |
| 火花 | 烟花绽放前那种往上窜的小点（用户说这条"还可以"），颜色跟音高 | 1.3s |
| 余辉 | 顶面留 3 颗不透明小色点，1.6s 缩没（旧版 alpha 0.10 的色斑在光影下等于看不见） | 1.6s |

### 20.3 调特效的入口（新增）

站在音符盒上看、或站在远处指定坐标：


可以一次录多个音高的对照（测完发现只有第一条命令被处理 → 参数要写成字符串 `-MidiList "..."`）。

### 20.4 还没解决的

## §21 音符盒特效 v3（0.8.1，2026-09-24 晚）

用户复看 0.7.9 实机（`mc-174337.log` 17:44–17:48 段 + 逐帧）后的原话：
**"只有 12 条棱的描边立方体和上方散发的发光颗粒可见，其他效果都没看出来"**。

### 21.1 三个真根因（都有日志/代码取证，别再凭猜测回退）

1. **涟漪命令从来没解析成功过**（这才是"没看出来"的第一原因）。
   0.7.9 的 `flareRipple()` 拼字符串时 `age` 后面**少一个空格**，Brigadier 直接报
   `参数后应有空格分隔，但发现了紧邻的数据 at position 112`，每条音都失败：

   ```
   [17:44:01] [Server thread/WARN]: [styxshow] 命令失败（第 1 次）：CommandSyntaxException ...
   ... 15 0 0 0 24<--[HERE] ← particlex image-matrix end_rod -0.3 113.45 -4.7 ring.png ...
   ```

   日志里每场只打印前 8 条（`failed <= 8`），实际是**每一颗音**都在失败。
   教训：命令模板改完必须跑 `/nbm machine showcheck`（22 条全过），它会把"少空格/多尾巴"都抓出来。
2. **平铺的水波/柔光在"与海平面平行"的机位下被压成一条线**。用户的运镜是"从音符盒上方扫到末尾"，
   镜头俯仰≈0，水面上的平面在画面里只剩一条细缝 —— 所以"顶面上方 0.45 格的一圈点"根本看不见。
   v3 起所有元素都带**真实竖直尺度**（壳层 / 环的上下起伏 / 火花）。
3. `image-matrix` 的坑（v3 中途踩到并修掉）：
   * 每颗粒子的"中心"= **命令点**。0.7.9 把命令点放在**贴图左下角**，
     于是 `(vx,vy,vz)=(dx,dy,dz)*k` 把整圈一边膨胀一边以 ~6 格/秒斜着推走（环根本不在方块附近）。
     现在命令点 = 环心，`dx/dz` 才是半径方向；
   * 矩阵平移量是在**除以 dpb 之后**才乘上去的（`pos = M·(像素/dpb)`），所以平移要写"格"
     （11.5/15 = 0.7667），写像素值会把整圈丢到 11 格外去（第一版就是这么翻的）。

### 21.2 v3 一颗音放什么（0.8.1 现行）

| 元素 | 做法 | 寿命 |
|---|---|---|
| 12 条棱 | 不变（描边立方体，用户认可）；锚点回到**方块中心** y+0.5（0.7.9 的 y+1.5 让框悬空了一格） | 1.1s |
| **盒体表面发光** | `custom-conditional` 在 ±0.5 壳层上按 **step 0.125**（9³ 采样 → 337 颗）铺点，size 1.4（四边形≈0.19 格）互相压住 → 贴在盒面的一层细密辉光；`0.032*dx³` 让每颗沿面法线慢慢外渗 | 0.5s |
| **涟漪（阵阵水波）** | `image-matrix` + `ring.png`（连续细环，116 颗/圈）：每阵晚 **0.15s** 出生（`pulse()` → `Pending` 延迟队列），同处落点向外荡 `0.12/(1+t/3.5)`，`vy=0.04*sin(t/2.2+ds1*3)` 给整圈叠行波 | 1.0/1.1/1.2s |
| **落点迸溅** | 水皮上一小簇向上窜的水花（10 颗，带重力回落） | 0.65s |
| **手持烟花** | 细而快的小火星：size 0.8（≈0.1 格）、初速 0.30–0.62 格/刻、重力 0.05、阻尼 0.98 | 0.75s |
| 余辉 | **删掉**（顶面那 3 颗平铺点在平飞机位下同样看不见） | — |

* 水面高度口径：水方块与音符盒同在 y=110 → 水皮 = 顶面 − 0.02 格（`RIPPLE_DROP`）；
  涟漪、迸溅都贴水皮，棱框/表面光挂方块中心。
* `size` 的真实语义（逐帧实测）：四边形边长 ≈ **size/8 格**（不是 size/4）。
  所以"在 0.125 格间距上铺满"要把 size 写到 1.4 左右；0.75 就会变成一粒粒孤立的点。
* 预览（`/nbm machine flare`）不在视效层里跑、没有延迟队列的滴答源，
  所以三阵改用"更大的出生半径"错开（矩阵 scale 1.0 / 1.45 / 1.9）；机器跑的时候才是每阵晚 0.15s。
