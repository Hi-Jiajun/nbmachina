# M1-3 实测报告 · 起音补漏（分频带多分辨率检测器 + 谱面补音）

任务书：`nbforge-m1-3.md`（M1 第 3 条）。数据：`build/styx_helix_full.wav`（mono 44.1kHz，281.4s）
＋ `build/machine_p1.csv`（M1-1 之后的机器谱面：2805 颗音 / 1821 个起音，撞格 0）。

**一句话结论**：任务书里"起音 recall 0.805 是因为检测器太保守"**成立**——换成 6 带多分辨率谱通量后
**R 0.805 → 0.974（P 0.970）**，客观分 0.9467 → 0.9677，八度命中率 0.965 不变。
但"因此旋律缺音"那一半**不成立**：同一把尺子量下来，谱面 1821 个起音、音频 1829 个起音，
真正"音频有攻击而谱面 50ms 内一颗音都没有"的位置只有 24 个，而这 24 个**没有一个**通过音级证据门槛
（19 个是低音区不可判、3 个是前音的衰减/拍频、2 个是同一颗音的量化差）。也就是说：
**R 0.805 是检测器的问题，不是谱面缺音**——这与 M1-1（"音级不是被吸附的错音"）是同一个方向的结论。

## 3. 检测器口径（每条取值为什么这么定）

全部常量在 `DEFAULT_ONSET_DETECT_CONFIG` / `DEFAULT_ONSET_BANDS`，CLI 与 `scoreChart({config:{onset:{banded:{…}}}})` 都可覆盖。

### 3.1 分频带（6 带）＋ 多分辨率（逐带帧率）

| 带 | 频段 | 帧长（分辨率） | bins |
|---|---|---|---|
| b1 | 60–125 Hz | 20ms | 3 |
| b2 | 125–260 | 20ms | 7 |
| b3 | 260–540 | 10ms | 13 |
| b4 | 540–1100 | 10ms | 26 |
| b5 | 1100–2200 | 5ms | 51 |
| b6 | 2200–6000 | 5ms | 176 |

为什么这么切：M0 的单带检测器把 60Hz–8kHz 的正通量**求和**，低音的强攻击会把整条曲线的局部均值抬起来，
旋律的相邻攻击就够不到 1.5× 局部均值（任务书说的"并成一个峰"）。逐带各自取峰后，一个带里的强音
不再压制另一个带。低频给 20ms 帧率是省算力且够用（低音起音本身不锐），高频给 5ms 是为了让
16 分格里的相邻攻击落在不同帧上。

**"≥4 带"的边界**：实测带越窄越差——把 6 带拆成 8 带（50/90/160/280/500/900/1600/2800/5000Hz 边界）后
真实数据 **R 0.81 / P 0.96**（比 6 带差 16 个百分点）：窄带里一颗音只能点亮 1–2 个带，
"≥3 带同时看到"这条闸门把真起音也拒了。所以默认 6 带（≈一个倍频程一带）是实测最优点。

### 3.2 窗长统一 46ms + 延迟补偿 0.5×窗长（多分辨率放在时间维）

加窗通量的峰出现在真实起音**之前**：冲击进入 Hann 窗上升段时通量增量最大。这条标定做成了
模块内的 CLI（合成长音点击、每颗真值取 ±150ms 内最强峰），随时可复现：

```
> node src/analyze/onset-detect.mjs --calibrate
窗长(ms)  帧长(ms)  峰−真值 均值 / 中位 / 标准差 (ms)   窗长/4   提前量/窗长   ≤50ms 命中
      6       1.5     -1.9 /   -1.9 /    0.4       1.5        0.32       20/20
     12       2.9     -5.2 /   -5.1 /    0.9       2.9       0.438       20/20
     23       5.8    -12.1 /    -12 /    1.6       5.8       0.518       20/20
     46      11.6    -38.6 /  -29.1 /   21.2      11.6       0.626       16/20
     93      23.2   -104.1 / -106.5 /   16.3      23.2       1.146        0/20
    186      46.4   -164.5 / -163.8 /   17.8      46.4       0.882        0/20
```

补偿取 `t = 帧号×帧长 + 0.5×窗长`（实测 0.5–0.7×窗长；在 0.4/0.5/0.6 三档下真实数据结果**完全一样**，
见 §3.6，所以这个系数不敏感）。**不补偿**（系数 0）时真实数据 R 0.9638 → 补偿后 **0.9742**（+1.0 个百分点）。

### 3.3 突出度 + 四道闸门

- **突出度** = 该带通量峰 / 该带 ±100ms 局部均值（逐带按帧率换算成帧数）。
- 逐带入选：突出度 ≥ **1.2**（只是"这是个峰"的地板，主力闸门在下面）。
- 一个起音要被 ≥**3 个带**在 ≤35ms 内看到（跨带合并），且：
  - 最强带突出度 ≥ **4**（或走 §3.4 的备用通道），
  - 最强带归一化通量 ≥ **0.1**（该带全曲最大值 = 1），
  - 起音处 23ms 混音 RMS ≥ **0.02**（挡静音/底噪里的假峰；静音与 3e-3 白噪声实测 0 个起音）。
- 闸门效果（真实数据实测）：`峰 15255 → 簇 4315 → 起音 1829`，被拒的 2486 个簇中
  **带数不足 1588、突出度不足 822、太静 4**。

### 3.4 备用通道：宽频一致（"不挑但很一致"也算证据）

慢起振/弱奏的音在 ±100ms 局部均值里抬不起 4 倍突出度，但会**同时**出现在多个带上。
所以给一条并列通道：**带数 ≥5 且归一化通量 ≥0.5** 也算通过。
实测：真实数据**逐位不变**（P 0.9699 / R 0.9742，与被关掉时完全相同），
而合成 32 分格（0.06s 网格，32 步）的漏检 1 → **0**。这条通道只在"别人都不出挑、但它很一致"时兜底。

### 3.5 为什么默认**不**用"逐带不同窗长"的多分辨率

| profile | 真实 P | 真实 R | 合成密集 16 分格漏检 |
|---|---|---|---|
| **默认：统一 46ms 窗 + 逐带 20/10/5ms 帧率** | 0.9699 | **0.9742** | 0/32 |
| 统一 46ms 窗 + 全部 10ms 帧率 | 0.9584 | 0.9621 | 0/32 |
| 统一 46ms 窗 + 全部 20ms 帧率 | 0.9904 | 0.9616 | 0/32 |
| 逐带不同窗长 93/46/23ms（+逐带延迟标定 0.65/0.5/0.35） | 0.9977 | 0.9451 | 1/32 |

读法：**窗长决定通量峰的提前量（§3.2）**，混用窗长后各带的峰在 50ms 容差内互相错位——
精度上去了（0.9977），recall 掉下来（0.9451），合成密集段也开始漏。所以"多分辨率"落在
**时间维**（逐带帧率 20/10/5ms，低频省算力、高频抓密格），窗长保持统一。异窗 profile
仍然可用（`config.bands[].frameSize` + 逐带 `latencyFactor`，单测里有用例）。

### 3.7 合成对照（含"合成信号本身要成立"这件事）

合成模型：每颗音 = 基频 + 2/3 次谐波（含轻微非谐性）、10ms 起振、~0.28s 指数衰减、
**击槌噪声 6ms**、±5 音分失谐。后两项是真实钢琴都有的。

| 合成用例 | 真值 | 现有单带 检出/漏 | 分频带 检出/漏 |
|---|---|---|---|
| 16 分格 ×16 步（旋律+低音同格，等力度） | 16 | 16 / **0** | 21 / **0** |
| 16 分格 ×32 步（等力度） | 32 | 32 / **0** | 37 / **0** |
| 16 分格 ×32 步（旋律弱 / 低音强） | 32 | 32 / 0 | 37 / **0** |
| 32 分格（0.06s 网格）×32 步 | 32 | 32 / 0 | 35 / **0** |
| 16 分格 ×32 步（只有旋律，无低音） | 32 | 32 / 0 | 39 / 1 |
| 慢起振 30ms（无击槌噪声） | 32 | 37 / 0 | 19 / **18** |
| 慢起振 60ms（无击槌噪声） | 32 | 34 / 5 | 15 / **21** |
| 强低音压旋律（慢起振 40ms） | 32 | 39 / 4 | 26 / **11** |
| 弱击槌 0.3 | 32 | 32 / 0 | 36 / 3 |
| 弱击槌 0.15 | 32 | 34 / 0 | 26 / **11** |
| 纯谐波叠加（无击槌噪声/失谐，16 步） | 16 | — / 0 | — / **5** |

**两件必须写下来的事**：

1. **任务书说"现有检测器会漏"这条只在纯谐波模型下成立**。第一版合成是"3 个纯正弦叠加、完全同相、
   无起振噪声"——相邻音的谐波在谱上相加时会互相抵消（对数幅度会**下降**），通量因此不可用。
   这是合成信号不成立，不是检测器漏检。给合成音加上真实钢琴都有的击槌噪声后，现有检测器在这段
   合成上并不漏（16 分格 0/32）——**它真正漏的是真实混音里的密集段（R 0.805 vs 0.974）**，
   也就是 §1 那条 head-to-head 对照。
2. 任务书要的"合成 16 分格漏检必须为 0"作为**回归测试**成立：16 分格 0/32、0/16，32 分格 0/32。
   已知边界是**慢起振/弱击槌**（§5.2）：这类音在 ±100ms 里既不突出、点亮的带也不够，会漏；
   现有单带检测器在慢起振上反而更好（0/32 vs 18/32）。这两个口径的取舍写进 §5.2，没有藏。

### 4.2 结论：这一版**补出 0 颗**——不是"补不动"，是"没有可补的"

24 个未覆盖起音 → **0 个**通过全部门槛：19 个 `below-margin`（音级判不出，其中 17 个落在低音区）、
3 个 `decaying-tail`、2 个 `same-attack-as-chart`。逐条理由与证据见上表 / `build/onset_recover_report.json`。

其中 #12（95.583s）是唯一"像新攻击、音级边距却差一点点"的：能量比 **6.50×**（确实是新攻击的样子），
但音级边距 **1.590** vs 门槛 **1.600**。它距离最近的谱面起音只有 **57ms**
（谱面 95.640s 处是 **E6**，而这里判出来的候选音级是 **G#6**）——两种可能：
① 同一次攻击的时间量化差（谱面把它量化到了 95.640s，而检测器提前了 57ms），此时"G#6"是误判；
② 真有一颗谱面没有的 G#6。**光凭窄带能量分不开这两种**。把它放进来只需要把 margin 从 1.6 调到 1.58，
但那等于把 M1-1 定下的证据门槛改松（当时就是为了挡这类"差一点"的候选），所以按原口径不补，如实记录。

### 4.3 三道"防假补音"闸门（都是被实测逼出来的）

第一版实现（只有音级/八度/RMS/振幅门槛）在真实数据上补出 **4 颗**：
52.583s G#6、212.483s D#6、224.463s G#6、246.833s B5。逐颗复核后**全部是假的**：

| 补出的音 | 该音自身能量：120ms 前 → 检测时刻 | 该音所在带（b5）的通量 | 谱面同音高最近音 |
|---|---|---|---|
| 52.583s G#6 | 2.49e4 → 2.07e3（**8%**） | 0.000（谱面起音处中位 0.148） | 52.320s 的 G#6（+263ms） |
| 212.483s D#6 | 3.92e4 → 1.79e4（46%） | 0.007 | 212.400s 的 D#6（+83ms） |
| 224.463s G#6 | 1.58e4 → 2.23e4（上升） | 0.003 | 224.400s 的 G#6（+63ms） |
| 246.833s B5 | 4.61e4 → 1.58e4（34%） | 0.015 | 246.720s 的 B5（+113ms） |

于是加了三条闸门（现在都在默认链路里）：

1. **`decaying-tail`**：候选音自身在 t 与 t−0.12s 的能量比 < 1.25 → 不是新攻击，不补。
2. **`same-attack-as-chart`**：谱面在 0.12s 内已有**同音高**的音 → 这是同一次攻击的量化差，不重复补。
3. **`duplicate-cell`**：同一 `(step, midi)` 已有音 → 不重复补（原有）。

这三条也是"合成用例里 3 颗幽灵音被拦掉"的同一条闸门：合成尾段（3.32/3.44/3.56s，谱面已结束）
检测器会因拍频报起音，补漏现在会拒掉它们（`decaying-tail`）。

### 4.4 有真漏音时它确实能补（合成对照）

把 24 步的 16 分格旋律**从谱面里删掉 12 颗**（音频不变），补漏结果：

```
合成漏音 12 个 → 补出 10 个（全部音级/八度正确），未补 2 个：2.0278s/below-margin 2.5088s/below-margin
```

- 补出的 10 颗：`step/tick/time_seconds` 全部落在 0.12s 网格上，**音级与八度全对**
  （测例里断言"补错音级比不补更糟"，见 `tests/onset-recover.test.mjs`）。
- 未补的 2 颗：音级边距 1.578 / 1.589（差一点到 1.6），如实记 `below-margin`。
- 原有行逐字符保留（测例逐行断言），新行追加 `origin=recovered` + `recoverReason` + `recoverMargin`。

### 4.5 结论：谱面在"起音"这一维基本完整

音频 1829 个起音 vs 谱面 1821 个起音，1774 个直接对齐（R 0.974）；剩下 47 个未对齐的谱面起音里
绝大多数是表演与量化之间的时间差；而"谱面完全没有音、音频却有攻击"的位置只有 24 个，
其中没有一颗能凭证据判出音级。**所以"检测器太保守导致旋律缺音"这个诊断，前半句对、后半句错**：
检测器确实错（已修，R 0.974），但谱面没有因此少掉一颗能证据化的音。这与 M1-1 的结论
（"音级不是被吸附的错音，谱面基本完整"）互相印证。

## 5. 限制与如实定级

1. **低音区（midi < 48）判不出音级**：44.1kHz / 100ms 窗的主瓣 ≈20Hz，而 D2 与 D#2 只差 4.4Hz——
   一个半音不到一个 bin。实测：**单独一颗**低音（没有别的音同时响）音级边距也只有 1.00–1.19
   （midi 52/55 才到 1.82/2.64）。长窗能不能救？实测把窗拉到 0.2/0.3s 后，19 个低音区候选里
   有 6/11 个"达标"，但**答案会变**（例：254.463s 从 A#0 变成 C#4、261.243s 从 A0 变成 B5）——
   长窗把**下一颗音**算了进来，不是这颗音。所以默认不补低音区，与 M1-1 的贝斯结论一致。
2. **慢起振 / 弱击槌是已知边界**：这类音既不突出、点亮的带也不够（§3.7 表）。现有单带检测器在
   慢起振上更好（0/32 vs 18/32），代价是它在**真实混音**的密集段差得多（R 0.805 vs 0.974）。
   本项目音频是钢琴（击槌瞬态），默认口径按它定；换成弦乐/慢起振素材应另设 profile
   （把 `minPeakProminence` 降到 2、`minBands` 降到 2，代价是真实数据精度 0.93）。
3. **#12 那颗边界音没有补**（边距 1.590 vs 1.600），理由与代价写在 §4.2。
4. **口径变了，`docs/BASELINE.md` 已同步**：默认检测器换成 banded，旧口径用 `--detector legacy`
   复现（R 0.805 / F1 0.888 / 客观 0.9467）。横向比较起音指标必须同口径——BASELINE §4.3 原本
   就写了这条规则，本次照做并留了腿。
5. **运行时变长**：`score.mjs` 单跑 1.8s → 4.0s（6 带 × 多帧率，峰 15255 个），
   全仓库 `npm test` 10s → 30s。可以靠"高频带帧率 10ms"省 30%，但实测 R 0.974 → 0.962，不划算。
6. **仍然没有听测**：`overall` 依旧 `null`（人耳清单 30% 未录）。本报告所有结论都在客观指标与
   逐音能量层面。
