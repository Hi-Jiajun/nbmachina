# M3-38 · 回到"音符盒本体发声"（触发道方案实现）（2026-09-19）

用户："先试试吧"（= 按 M3-37 的结论实现 B 方案：让音符盒真的响，mod 只负责换音色）。

## 1. 结论先行

M3-37 的实验证明"水平相邻红石块 → 音符盒响"。而现有密集单排布局里**每个音符盒都能找到一个
水平相邻的空位**（用 machine_map 全量核过：**3044/3044，缺失 0**，其中 2905 个首选 z+1），
所以**不需要重建机器布局**，只改数据包与摆块函数即可。

## 2. 改了什么

| 位置 | 改动 |
|---|---|
| `src/emit/trigger-map.mjs`（新） | 触发位**单一来源**：占用格 = 灯(y-1)/甲板(y)/音符盒(y+1)/旧触发位(y+2)，在音符盒同层按 `z+1 → z-1 → x+1 → x-1` 找空格；一格只归一颗音（避免放置/清除打架） |
| `src/emit/note-blocks.mjs` | 摆块时把触发位**清成空气**（这样"放红石块 → 拆掉"恢复的是空气，不会把地形挖洞）；算不出触发位就直接报错 |
| `src/emit/datapack-playback.mjs` | 每颗音：**提前一刻**放红石块 → 下一刻拆掉；默认 `#nb=1` + `#snd=0`（音符盒本体发声）；新增 `play/clear_triggers`，`stop`/`reset` 兜底清空所有触发位 |
| mod `NbmachinaNoteBlocks` | 位置查表补一层 fallback：`machine_map.csv` 记的是**甲板**格，方块事件给的是**音符盒**格 → 先查原位置、再查 `y-1`。修好之后音符盒路线才能拿到**逐音力度/时值/乐器**（否则退回"力度写死 100"） |
| 刻补偿 | 方块事件是排队到**下一 tick 开头**执行的 → `--trigger-lead 1`（默认）把红石块提前一刻放，声音才与灯/粒子/时刻表对齐。可用 `--trigger-lead 0` 关掉对比 |

两条路互斥、随时可切：

```
/function styx:play/sound_off   → 音符盒本体触发（默认；装 mod = 无损音色，没装 = 原版音符盒声）
/function styx:play/sound_on    ← 数据包直派 mod 引擎（旧口径，/nbmc play 那套也走这档）
```

## 6. M3-38b · 真机首测暴露的三个问题（2026-09-19 11:00，全部已修）

用户实测："虽然现在可以听到了，但是歌曲完全不对" + "没看到方块重置"。逐条查实：

| # | 现象 | 真因 | 处置 |
|---|---|---|---|
| 1 | **歌曲完全不对**（只听到身边一小段） | `NbmachinaNoteBlocks.onNoteBlockEvent` 里写死"只发给 48 格内的玩家"，**没有走监听模式**；机器长 2880 格 → 站哪儿都只听到身边几十格 | 改成与 `/nbm playat` 同一套派发口径：监听模式（默认 on）声音锚在玩家身上、不做距离过滤；`listen off` 才按方块位置发 64 格内 |
| 2 | 有**多出来的音** | 触发位只检查了"这一格自己空不空"，没检查"红石块会不会同时点亮旁边的音符盒"——全量算下来 **309/3044 个触发位会多点亮一个音符盒** | `trigger-map.mjs` 改为**严格优先**：触发位必须只挨着目标音符盒；剩下 **18/3044** 颗音没有严格位 → 改走 mod 引擎兜底（`if #nb matches 1 run nbm playat`），不再多点亮 |
| 3 | `/nbmc selftest` 报"存在=false / 解码失败" | selftest 自己**没有解析相对采样根**（直接 `Path.of(region.file)`），播放路径其实是好的 | selftest 改走 `NbmachinaSamples.resolve()` |

另外修掉两个会让人误判的坑：

- `styx:redo/s4` 里的 `nbmachina listen on` 是**改名前的残留命令**（应为 `/nbm`），导致**整个 s4 函数加载失败**——重做链最后一步永远走不到（不 listen、第三段不重建、**不自动播放**）。这就是"为啥还没开始"的真因；离线 lint 只查函数引用、查不出 mod 命令名，需要人工在改名后 grep 旧命令名。
- 周期日志用 `eventCount % 50` 打点，而单机里事件数是"客户端+服务端"交替的**奇数**，所以 50/100/150 永远打不出来 → 改为按**派发次数**每 200 条打一行。

校验（离线）：`verify-trigger-map` → 严格触发位 **3026/3044**、引擎兜底 18 颗（lo/hi 各 18 行）、放/拆成对无重复 ✔；lint 793 函数 ✔；数据包已重新装包。
