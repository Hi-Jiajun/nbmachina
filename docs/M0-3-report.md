## 1. 口径（全部写进代码常量与 JSON，报告抄一份）

### T5a · chroma（`src/analyze/chroma.mjs`）

| 项 | 取值 |
|---|---|
| 分帧 | **8192 点 Hann 窗 / 4096 点 hop**（44.1kHz → 185.8ms 窗、92.9ms 步进，全曲 3028 帧） |
| 频带 | 55Hz（A1）– 4186Hz（C8） |
| 折叠 | 每个频点按**连续 midi 就近取整**得到音级，累加该频点功率（`|X(k)|²`） |
| 归一化 | 逐帧 l1 归一；`meanRaw` 保留原能量累加；谱面侧 `count` 权重（每颗音 1 票） |
| 相似度 | 两侧都 l1 归一后的**余弦**；另算 12 个半音循环移调里的最好者 |

窗长取 8192 而不是常见的 4096：44.1kHz 下 4096 点是 10.8Hz/bin，而低音区一个半音只有 4.3–6.9Hz，
折叠时会偏出半音；8192 点是 5.38Hz/bin。

### T5b · 力度（`src/arrange/velocity.mjs`）

| 项 | 取值 | 为什么 |
|---|---|---|
| 描述子 | 该音**自己的音级 + 自己的八度**上 `f0` 处加窗 DFT 功率 `|X(f0)|²` | 就是任务书要的口径：量"这颗音弹多重"，而不是"这段混音多响" |
| 谐波 | 只用基频（不加 2f0/3f0） | 加 2f0 会让 C4 把"只响着的 C5"算成自己的一半能量（相邻八度同音级互相污染）；单测覆盖 |
| 窗长 | **旋律 100ms / 低音 120ms**（Hann，从音符起始对齐） | 低音区一个半音 < 1 个 bin，窗太短会把前一颗音的衰减尾巴算进来；见 §3.3 的窗长扫描 |
| 无证据 | 窗内 RMS < 0.01 → 力度 **0**（`velocityReason=weak`） | 这不是"很轻地弹了一下"，而是"音频里听不出这颗音" |
| 映射 | 全曲能量 **p10 → 0.35、p90 → 1.0**（线性，超出截断） | 沿用现状的映射（DISCUSSION-C §4.2），只换物理量 |
| 退化 | 分位数跨度为 0（全部能量相同 / 只有一颗音）→ 统一退到地板 0.35 | 不凭空给天花板，也不产生 NaN |

### T6 · 五项指标（`src/verify/score.mjs`）

| 指标 | 口径 | 权重 |
|---|---|---|
| ① 起音对齐 F1 | 音频：1024 点 STFT / 10ms hop 的**对数谱通量**，峰值拾取（全局阈值 = 均值 + 0.5σ、局部均值×1.5、最小间隔 50ms）；谱面：不同起音时刻；**容差 50ms 最近邻匹配** → F1 = 2PR/(P+R) | 0.25 |
| ② chroma 相似度 | 音频整曲折叠式 chromagram（§T5a）与谱面音级直方图的余弦（都 l1 归一）；另报局部 4s 窗均值与最佳移调 | 0.20 |
| ③ 八度命中率 | 逐音在该声部音域内的候选八度上量 `|X(f0)|² + ½|X(2f0)|²`，取最大者；与谱面 midi 完全一致 = 命中。**独立实现**（不做 T2 的谱白化、只用 2 个谐波），可与 T2 证据对拍 | 0.25 |
| ④ 力度包络相关 | 谱面力度（velocity 列，或退回混音 RMS）与该音窄带能量的 **Pearson r**（描述子先 p10–p90 归一到 0..1；负相关在打分时夹到 0）。另报 Spearman ρ、与**同窗混音 RMS** 的相关、与**音频起音强度**的相关 | 0.15 |
| ⑤ 有支撑率 | 谱面有、且音频在该 (音级+八度) 上有可测能量（阈值 = 0.1 × 全曲能量中位数）的比例；给了 `--expected` 时另算基准对比的漏音率/多音率 | 0.15 |

权重理由：音乐组把"旋律音级与走向、重音位置、低音根音进行、16 分格节奏"列为**必保项**
（DISCUSSION-C §2.1）——节奏由①、音高由③、和声色彩由②承担；力度与漏音是次级损失。
`overall = 0.7 × 客观 + 0.3 × 人耳清单`（SPEC §6）；人耳清单没录进来时 `overall = null`，
**不编造一个人耳分**。权重可用 `--weights '{"octaveHit":0.3}'` 覆盖（按比例归一）。

## 3. 实测发现（哪几项弱、为什么）

### 3.1 弱项一：音级（chroma 0.936，但差值集中在 5 个音级上）

余弦 0.936 看起来不低，是因为调内 7 个音级占了大部分能量，把缺席的 5 个音级的差异"平均掉"了；
把口径拆到音级一级就看得很清楚（§2.2 那两行占比）：**音频里明明有的 5 个音级，谱面只给了 1/3 到 1/11 的量**。
听感后果：离调色彩、副属和弦、转调全被听成"平"的（DISCUSSION-C §2.4 第 5 条）。

**为什么**：这是**输入的问题**，不是本轮的实现问题——转谱把音高吸附到了一个音阶。
本轮只负责"量出来"，不负责"修"（T5 任务书里没有音级修复模块；真正的修法要用音频做逐音音级判定，
再写回 midi，属于 M1）。

### 3.2 弱项二：八度（0.844，贝斯 0.779 明显拖后腿）

同一份数据的两个独立口径互相印证：

| 口径 | 旋律 | 贝斯 | 合计 |
|---|---|---|---|
| 我的独立估计器（`|X(f0)|²+½|X(2f0)|²`，声部音域内取最大） | 0.895 | 0.779 | 0.844 |
| T2 的 evidence（谱白化梳状 + 音域先验，`analysis_octave.json`） | 0.899 | 0.752 | 0.834 |
| 两者逐音一致率 | — | — | **95.4%**（3099 颗音） |

两个独立实现给出同量级的结果（而且逐音一致 95.4%），说明这个数字可信；
它也和 T2 的第三方谱峰基准一致：输入里贝斯的错误集中在 `midi ≤ 23`（那一段只有 35.8% 正确）。
**修完之后（T3 的 `notes_fixed_v3.csv`）这一项 0.844 → 0.954**（贝斯 0.779 → 0.941）。

### 3.3 弱项三：力度（v3 的 r=0.361，而且口径本身有噪声底）

v3 的"力度"是混音 RMS，所以它与混音 RMS 的相关是 0.930（自己跟自己），
但与**音频起音强度**（谱通量，非循环量）的相关是 **-0.155** ——
也就是说，**现在的力度曲线对"哪里是重音"几乎没有信息**（甚至是反向的）。

换成新口径（`velocity_fixed.csv`）后，力度包络相关 r=1.000，但必须如实说明：
**这是"链路自检"而不是独立证据**（力度就是从同一个描述子算出来的）。
我对这个口径做了两类独立实验，把它的噪声底量化出来，写进这里：

**实验 A · 窗长扫描（合成的贝斯线，0.12s 步进，每个音高重复 7 次）**
衡量的是"测得的能量 vs 真实增益²"的 Pearson r：

| 窗长 | 80ms | 120ms | 200ms | 300ms |
|---|---|---|---|---|
| 贝斯线 r | 0.571 | **0.851** | 0.813 | 0.910 |
| 旋律线 r | 1.000 | — | — | — |

原因：44.1kHz 下 80ms 窗的频率分辨率是 12.5Hz，而 E2（82.4Hz）的一个半音只有 4.9Hz——
**相邻半音整个落在同一个主瓣里**，而 0.12s 之后前一颗音还有 71% 的幅度。
所以低音声部的窗取 **120ms**（正好到下一颗音的起始；再长会把下一颗音的攻击算进来）。
真实数据上"相邻半音能量 / 本音能量"的中位数是 **0.93**，说明这个污染在混音里同样存在，
它给低音力度带来的是**系统性方差**，不是零均值噪声。

**实验 B · 与"起音强度"的一致性问题（如实报告，不改口径掩盖）**
新力度与音频起音强度的相关是 **-0.532**。两者量的不是一件事：
谱通量在"密集段/低频鼓点齐发"时最大，而基频窄带能量量的是"这颗音自己在窗内有多响"，
在密集段反而被掩蔽。结论：**新口径解决了"力度不是混音响度"这个问题，但还没有证明它等价于
"听起来弹得多重"**。要把力度做成有音乐意义的量，需要人工 A/B 或改用"起音强度/宽频包络"口径（见 §6）。

### 3.4 起音对齐（F1 0.888，是"检测器保守"而不是"谱面对不上"）

| 全局阈值 | 检出音频起音 | precision | recall | F1 |
|---|---|---|---|---|
| 均值 + 1.0σ（初版） | 1383 | 1.000 | 0.759 | 0.863 |
| **均值 + 0.5σ（采用）** | 1481 | 0.990 | 0.805 | **0.888** |

precision 接近 1（检出的音频起音几乎都能对到谱面上），说明这条链路的对齐是真的；
recall 只有 0.805 是因为检测器**保守**：密集的 16 分格段落里，相邻音的攻击会并成一个峰。
这也说明 F1 的上限由检测器决定，比较"同一检测器下的不同谱面"才有意义（这正是评分的用法）。

### 3.5 漏音率（v3 1.3%，但换个基准立刻变成 9.4%）

v3 的 3099 颗音里 98.7% 都能在音频里找到支撑（阈值 = 0.1 × 能量中位数）——
因为原曲编曲很满，几乎每个时刻都有能量。所以**这个指标在"谱面 vs 原曲"的方向上偏宽松**，
它的真正用处是 `--expected`（基准 vs 结果）：

```
> node src/verify/score.mjs --notes build/notes_dedup.csv \
    --expected build/styx_helix_notes_v3.csv --out build/score_report_dedup.json
  ⑤ 有支撑率 0.986（漏音率 1.4%）
     基准对比：漏音 9.4%（291 颗）／多音 0.0%（0 颗）
```

去撞格丢掉 291 颗音，逐条记录在 `build/dedupe-report.json`（M0-1 §2.4），
这里在"分值"层面复现出这 9.4%——**基准必须同为去撞格口径**，否则会把这 291 颗算成漏音。

| v3 谱面 + 新力度口径 | 0.888 | 0.936 | 0.844 | 1.000⁽*⁾ | 0.987 | 0.9183 |
| `notes_fixed_v3.csv`（T2/T3 修八度）+ 重算力度 | 0.888 | 0.936 | **0.954** | 0.999⁽*⁾ | 0.985 | **0.9453** |

⁽*⁾ 这两行的力度相关是"链路自检"（力度由同一描述子生成），不能读成"力度变好了 0.6"。
真正的提升来自八度那一项：0.844 → 0.954。

**当前最弱的三项**：① 力度口径的音乐有效性（无独立证据，与起音强度负相关）；
② 音级吸附（5 个调外音级被压到音频的 1/3–1/11，综合分里只体现为 chroma 0.936）；
③ 起音 recall 0.805（检测器保守，密集段合并）。

## 5. 限制与已知边界（如实定级，不夸大）

1. **力度相关项有循环性**：谱面力度若由同一能量口径生成，这一项验证的是"链路没接错"。
   报告里始终同时给"与混音 RMS"和"与起音强度"两个诊断，后者才是非循环的那一面，
   而它目前是 -0.53（不好）。
2. **低音区的窄带隔离受物理限制**：一个半音 < 1 个 bin（§3.3 实验 A）。本口径用 120ms 窗缓解，
   没有消除；更彻底的做法是"峰锐度/多频点最小二乘"口径，属于 M1。
3. **起音 F1 的上限由检测器决定**：这是一个"保守检测器 + 50ms 容差"的指标，
   适合**同一检测器下横向比较**，不适合当作绝对正确率引用。
4. **八度指标用两个实现交叉验证**：我的独立估计器不做谱白化，在贝斯上偏宽松（0.779 vs T2 的 0.752），
   但两者逐音一致 95.4%，量级一致，所以基线可信；与第三方谱峰基准（T2 §3，覆盖 66.5%）一起看更稳。
5. **没有做人耳清单**：`overall` 一律为 `null`，`--human 0.8` 可以事后补录。
   按 SPEC §6 的口径，最终分 = 0.7 × 客观 + 0.3 × 人耳。
6. **`velocity_fixed.csv` 只追加列，不改原列**：`volume` 保持 v3 原值（布局/播放器仍在用它），
   新力度在 `velocity` 列里；等 M1 把 `score.json` 的 `velocity` 接进 layout 再统一切换。
   列顺序保持"原 7 列 + 追加"，`src/test/run-headless.mjs` 按位置读前 7 列不会受影响。
7. **`analyze/dsp.mjs` 是计划外的共享模块**：计划文件清单里没有它，但 chroma/velocity/score
   三处都要读 WAV、量窄带能量、读音符表 CSV，抽一份比三份各自漂移好。M1 建议按职责拆成
   `ingest/wav.mjs` + `ingest/notes-csv.mjs` + `analyze/dsp.mjs`（现在有 3 份 `readWav` 实现：
   `analyze/wav-rms.mjs`(CLI) / `analyze/octave-evidence.mjs` / `analyze/dsp.mjs`）。
8. **本轮没有做音级修复模块**：任务书的 T5 交付物只有 chroma/velocity/score 三件，
   "音级恢复"这一半（把吸附的音级写回）留给 M1，判定依据就用 T5a 的 chroma + 逐音窄带能量。

## 6. 下一步怎么改（按优先级）

1. **音级修复（M1 首要）**：对每颗音，在"相同音级"和"相邻半音"的候选上量窄带能量，
   用音频证据改写被吸附的音级；验收直接用 T6 的 chroma（目标：被压制音级从 3.4% 提到 ≥8% 且
   与音频的逐音级占比差 < 2 倍）。
2. **力度改成"有音乐意义"的口径**：候选是 (a) 该音的**起音强度**（谱通量在该音的频带内），
   (b) 宽频包络，二者都能给出"重音位置"信息；验收标准应是"与音频起音强度的相关 > 0.5"
   （现在 -0.53），而不是"与自己的描述子相关 = 1"。
3. **低音力度用峰锐度口径**：`E(f0) / max(E(f0·2^(±1/12)))` 或对 ±1 半音做最小二乘分离，
   把 §3.3 实验 A 里那 15% 的方差压下去。
4. **起音检测器升级**：per-band（分频带）通量 + 多分辨率，把 recall 从 0.805 提上去，
   让 F1 不再被检测器封顶。
5. **补人耳清单**：按 DISCUSSION-C §6 的 10 条抽查，用 `--human` 录进 `score_report.json`，
   得到真正的 `overall`。
6. **端到端回归（T7）**：`npm run arrange && npm run verify` 串起来，
   把"修前/修后"的综合分写进 CI 产物（现在这一步是手动的）。
