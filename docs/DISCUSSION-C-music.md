# 讨论 C · 音乐 / 编曲视角（nbmachina）

> 产出方：子代理 `agent_c_music`（对应任务书 `nbmachina-C-music.md`），背景见 `nbmachina-brief.md`。
> 本文只给结论与取舍，不含代码。文中所有数字都是本次在 `build/` 里的真实数据上实测的（口径见第 7 节）。

## 0. 结论先行

1. **现在这套音高数据不能直接当"原曲"用。** 旋律的**音级**大体可信（转谱 chroma 与音频 chroma 的最佳对齐就在 0 移调，r=0.87），但**八度、延音、力度**三项都不可信。
2. **"错音"不是折叠算法造成的，是输入造成的。** 我把现状贪心折叠按代码 1:1 复现（3099/3099 完全一致），再把四种折叠策略对拍：旋律的"音程方向反向率"从贪心 31.3% 只降到 DP 的 29.1%，"同音折叠"数在四种策略下几乎不变（旋律 109–113 / 低音 150–157）。而**同音折叠数恰好等于"输入里相邻两音相差整数个八度"的对数**（旋律 113 / 低音 157）——输入自己就有这 113+157 对翻八度的错误，折叠只是把错误原样暴露出来。
3. **贝斯声部最不可信。** 用原曲音频逐音标定八度：旋律 98.3% 落在转谱八度 ±1 内（86% 完全一致），贝斯只有 30.8%（多数差 +2~+3 个八度）。贝斯 1360 颗音里有 **596 颗（44%）写在 midi ≤ 29**，比音符盒最低的贝斯音（F#1 = midi 30）还低。
4. **必保 / 可弃**：必须保留的是**旋律音级与走向、重音位置、段落疏密、低音根音进行、16 分格节奏**；可以妥协的是**绝对八度、延音长度、内声部完整度、音色与混音**。
5. **声部要和乐器绑定，不要两件乐器都挤 0–24 行。** 同一 `row` 上 harp 与 bass 两种乐器方块的实发音高相差约两个八度（木类 = bass 更低），合起来可用音区约 4 个八度。建议：旋律 harp 行 12–24、内声部 harp 行 0–11、低音 bass 行 0–12、打击乐（stone→basedrum / glass→hat）固定行 0。
6. **立刻能做、且一定见效的一件事是去重/去撞格**：有 **276** 个 `(step,row)` 上叠了 ≥2 颗音（其中同声部完全重复 157 颗），它们共用同一个音符盒格 → 指令后写者赢，**必然漏音，跨声部时音色也会被覆盖**。
7. **0.12 s/步的网格成立**（2320 步 → 278.4 s，音频 281.4 s，差 1.1%；若按 0.125 s 则是 290 s，明显更差），起音只落在 0.12 s 的整数倍上。但项目自带的 `audio-tempo.mjs` 的输出（"240 ms → 250 BPM"）**不可信**，别拿它当依据（见 4.1）。
8. **力度要换口径**：现在的"0.12 s 窗整段混音 RMS"测的是"那一瞬间整段混音多响"，不是"这颗音弹得多重"（它与同 step 音符数的相关系数 r=-0.008，所以不是密度代理，但仍是**混音**代理）。替代口径见 4.2。

## 2. 问题 1：「依照原曲」在只有 25 个音高、两种音色下意味着什么

### 2.1 必须保住的（听不出就"不像原曲"）

| 要素 | 为什么必须保 | 机器上怎么保 |
|---|---|---|
| 旋律音级序列与走向（级进/跳进的方向） | 人耳靠"相邻音的高低关系"认旋律 | 折叠必须保持音程、保持原调；见第 3 节的 DP 方案 |
| 重音位置（每 2 拍一次的强拍） | 听感上"有没有劲"几乎全在这里 | 力度曲线 + 打击乐层（4.3 规则 R3） |
| 段落疏密对比（0–15 s 只有 68 颗，61–77 s 有 215 颗、169–184 s 有 216 颗） | 段落结构一丢，整首就变成"从头到尾一样吵" | 分段落调（高密度段才叠和声层/打击乐层，见 R4） |
| 低音线的根音进行 | 决定和声听感对不对 | 低音必须单独占一个音区，且不能和旋律挤同一行（见 3.3） |
| 16 分格节奏型 | 节奏一错整首就散了 | 0.12 s/步 + 100 tps 已解决，保持现状 |

### 2.2 可以妥协的（听感损失可接受）

- **绝对八度**：25 个音高（每件乐器）装不下钢琴音域，八度平移不可避免；但**同一段内不要来回翻八度**。
- **延音长度**：音符盒无法延音，用"同音重触发 + 音量衰减"近似（R1）。
- **内声部完整度**：把和弦压到 2–3 个最重要的音，丢掉内声部经过音。
- **音色与混响/立体声**：原版音色 + 资源包（第 5 节）都能接受。

### 2.3 三条可验证的成功标准

1. **旋律对齐**：把机器演奏录成 wav，与原曲做 onset 互相关，整曲平均偏移 ≤ 50 ms，且末尾漂移 ≤ 150 ms（当前 0.12 s/步相对音频总长差 1.1%，末期约 3 s，需要一次对拍确认）。
2. **零结构损失**：演奏结束 `#hits` == 去重后的音符数（3099 − 157 = 2942），且每个 `(step,row)` 上只有一颗音。
3. **"像不像"可量化**：机器演奏录音与原曲的（a）分段响度曲线相关 r ≥ 0.5、（b）onset 强度包络相关 r ≥ 0.6。

### 2.4 最容易被听出来的"错音"场景（按本项目实测排序）

1. **长音变脉冲**：原曲的保持音在数据里就是一颗 0.05 拍的脉冲 → 听感"每个音都在点一下"，抒情段落尤其明显。
2. **同音折叠**：113（旋律）/157（低音）处，两个不同音高的音被折成同一个 `row` → 听成"卡住的重复音"，而正确行为应该是级进或跳进。
3. **方向反向**：旋律 532/1701（31.3%）、低音 541/1336（40.5%）处，折叠后的音程方向与原谱相反 → 听成"旋律乱跳"。
4. **撞格漏音**：276 处，副歌和弦段最密（同刻最多 4 颗音）→ 和弦缺音、织体变薄。
5. **音级吸附**：非调内音（C/D/F/G/A#）被吸附到调内 → 离调色彩（转调、副属和弦）被听成"平"。
6. **八度错误集中在贝斯**：贝斯只有 30.8% 的八度与音频一致 → 低音线听上去"不在原位"。

## 3. 问题 2：音高折叠策略

### 3.1 四种策略对比（本次实测，输入数据相同）

判定口径：按 `(step, midi)` 排序后逐对比较"原谱音程方向"与"折叠后 `row` 音程方向"；"反向率"越低越好；"同音折叠"指原谱音程非 0 而折叠后为 0 的对数。

| 策略 | 旋律反向率 | 旋律\|跃迁\|≥6 | 旋律平均/最大跃迁 | 旋律同音折叠 | 低音反向率 | 低音\|跃迁\|≥6 | 低音平均跃迁 | 低音同音折叠 |
|---|---|---|---|---|---|---|---|---|
| a) 现状：按声部整体折叠 + 贪心就近（v3 实际） | 31.3%（532/1701） | 161 | 3.32 / 10 | 113 | 40.5%（541/1336） | 89 | 3.39 | 157 |
| b) 固定音区（每音就近取声部中心：旋律 18 / 低音 8） | 36.0% | 486 | 3.94 / 10 | 113 | 52.8% | 299 | 4.03 | 157 |
| c) 小节重置贪心（每 16 步重置参考音） | 32.6% | 216 | 3.52 / **20** | 109 | **38.8%** | 113 | 3.58 / **19** | 150 |
| d) 声部内 DP（Viterbi，λ=0.1） | **29.1%** | 173 | **3.20 / 10** | 113 | 41.7% | 90 | **3.29** | 157 |

（"反向率"= 折叠后音程方向与原谱相反的比例；"同音折叠"= 原谱音程非 0 而折叠后为 0 的对数；DP 的 λ=0 版本旋律反向率 29.2%、平均跃迁 3.17，差别在噪声范围内。）

**结论（很重要）**：四种策略里 d) 最好、b) 明显最差、c) 只赢在低音的反向率上却会造出 19–20 半音的怪跳。更关键的是——**同音折叠数几乎不随算法变化（150–157 对）**：在 a)/b)/d) 三种策略下它恰好等于"输入里相邻两音相差整数个八度"的对数（旋律 113、低音 157）。也就是说，"错音"的主因不是折叠算法，而是**输入的音高/八度本身错**。在修好输入之前，任何折叠算法的调参都是在打磨错误；修好输入后，再用 d) 把残余的八度跳压到最小。

### 3.2 推荐方案（按落地顺序）

1. **重建音符表（最高优先）**：以原曲音频为基准，重新生成"时间 + 基频 + 力度"三元组，至少修掉三件事：(a) 只在 7 个音级上的吸附；(b) 低音区的八度（贝斯有 596 颗写在 midi ≤ 29，全曲另有 320 颗落在 midi 0–23）；(c) 157 颗完全重复与 276 处撞格。判定用第 7 节的方法即可，不需要新工具链。
2. **声部与乐器绑定**（见 3.3），把"两件乐器都塞 0–24"改成"每个声部住在自己的行区间"。
3. **声部内 DP 折叠**，并把"音频测得的目标八度"作为先验项（λ≈0.1）：代价 = `|跃迁| + 8·[|跃迁|>7] + λ·|row − 目标行|`。λ=0.1 时最大跃迁仍只有 10 半音（λ=0 会出现 22 半音的怪跳）。
4. **极端音单独出清单**：所有被折回/被迫反向的音，导出成"改了八度的音"清单（step + 原音 + 实际音），在报告里告诉用户"这几颗音被换了八度"。这比"物理限制，接受"更有说服力，也便于人工复核。

### 3.3 声部-音区-乐器分配（推荐表）

| 声部 | 乐器（方块） | 建议行区间 | 说明 |
|---|---|---|---|
| 主旋律 | harp（sand/dirt/grass） | 12–24 | 用到 harp 的高音区，避免和低音撞行 |
| 内声部/和声 | harp 或 bell/chime | 0–11 | 只在副歌出现，音量压低 |
| 低音 | bass（oak_planks） | 0–12 | 木类 bass 本身低约两个八度，低音线放这里才有"根音"感 |
| 打击乐 | basedrum（stone）/ hat（glass） | 固定行 0 | 音高无意义，只做重音与律动 |

> 待复核：harp 与 bass 的实发音高差（两件乐器的定调关系）建议在游戏里用 `/playsound` 与原音对照确认一次；项目 `fix-instruments.mjs` 的实测注释（"贝斯音色本身很低"）与此一致，但**具体相差几个八度**需要一次实测数据。

### 3.4 关于"2 个八度折叠对极端音仍会折回"

- 结论：**接受折回，但要给出清单**（3.2 第 4 步），并且优先保证"折回只发生在乐句边缘"。做法是允许 DP 在乐句（4 或 8 步一单元）开头重置音区，这样越界只影响一句，不会连续好多句都在翻八度。
- 不建议为了塞下极端音而整体抬高/压低旋律：那会把 90% 的音推到不合适的音区，听感损失远大于个别音的折回。

## 4. 问题 3：节奏与力度

### 4.1 节奏：网格已验证，但别用 `audio-tempo.mjs` 的结论

- **0.12 s/步成立**：2320 步 × 0.12 s = 278.4 s，音频 281.4 s（差 1.1%，可能来自片尾余韵）；同样数据按 0.125 s（＝120 BPM 的 16 分）算就是 290 s，明显更差。把 onset 强度按 0.48 s 拍折叠成 16 个 30 ms 格，起音只出现在第 0/4/8/12 格（即 0.12 s 的整数倍），确认 16 分格。
- **拍长**：归一化 onset 自相关的峰是 0.96 s(0.70) > 1.92 s(0.67) > 0.24 s(0.64) > 0.48 s(0.61)。0.96 s / 0.48 s 互为倍数，仅凭包络分不清"拍长 0.48 s（125 BPM，每 2 拍一次强重音）"还是"拍长 0.96 s"。**但对机器没有影响**——播放是按"步"驱动的，拍号只影响我们怎么写文档。
- **不要用 `audio-tempo.mjs` 的输出**：它报"最佳周期 240 ms → 250 BPM"，同时打印"0.12 s/步 = 500 BPM 的十六分音符"（60000/120 的换算写错了）。原因是没有做归一化的自相关，会被短 lag 偏置主导（240 ms 与 20 ms 的 hop 比值正好是 24 帧）。
- **建议**：把"总时长对拍"做成验收项（机器演奏录音 vs 原曲，末尾漂移 ≤ 150 ms），这样 1% 级别的速度误差不会漏过去。

### 4.2 力度：换口径，否则力度曲线基本是"混音响度"

现状：从原曲 wav 在每颗音的 0.12 s 窗里取 RMS，按 p10/p90 映射到 0.35–1.0（实测均值 0.64；落到最低一档 0.35–0.48 的有 690 颗、最高一档 0.87–1.0 的有 534 颗，合计占两头约 40%，说明映射的截断很严重）。

问题：这个窗口里装的是**整段混音**（鼓、贝斯、弦乐、人声都在），所以它主要反映"这一段编曲有多满、混音多响"，而不是"这颗音弹得多重"。实测它与"同 step 音符数"的相关只有 r=-0.008，说明它不是密度代理，但仍是**混音代理**（同时说明现在的力度不是完全随机，能用，只是物理含义不对）。

替代口径（可执行）：

1. 对每颗音，取它**基频 ±1 半音**的窄带能量（含 2 次/3 次谐波），窗长 0.06–0.12 s，随音符起始对齐。
2. 按全曲分位数（p10/p90）映射到 0.35–1.0 —— 映射方式沿用现状即可。
3. 实测参考：我现在用"各八度窄带能量占比"做八度判定时，最强的候选八度平均能占到该音总能量的 0.62（旋律）/0.68（贝斯），说明**基频窄带是能分出音符的**，可以用来做力度。
4. 原版音符盒没有力度（音量固定）：力度只有在"监听模式"（`playsound`）或模组（NoteBetter）下有意义。建议把力度做成**监听/录像轨**，不指望实体机器表现强弱；若要实体机器也有强弱，用"同音双音符盒 + 距离衰减"近似（成本高，建议列为未来项）。

### 4.3 五条可执行的编曲规则

| 规则 | 做法 | 依据 |
|---|---|---|
| R1 长音 | 原曲里保持 ≥2 步的音，在第 2 步用同音高重触发一次、力度 ×0.75；≥4 步的每 2 步重触发一次（音量递减 0.85） | 数据里时值全是 0.05 拍，长音完全丢失；需要用音频的窄带能量衰减重建时值（同一基频能量连续 ≥0.24 s 视为保持） |
| R2 力度 | 用 4.2 的窄带口径替换整段混音 RMS；保留 p10/p90 → 0.35–1.0 的映射 | 现口径是混音代理 |
| R3 重音 | 每 2 拍（0.96 s）的第一拍把旋律力度 +0.15；打击乐层用 basedrum 落 step%8∈{0}、hat 落 {4,12}，力度固定 1.0 | 0.96 s 的 onset 自相关最高（0.70）；副歌段（61–77 s 等）密度是前奏的 3 倍 |
| R4 分层 | 内声部/和声层只在"每 15.36 s 音符数 ≥ 180"的段落出现（实测刚好是这 9 段：15–31 s、61–77 s、77–92 s、138–154 s、154–169 s、169–184 s、184–200 s、246–261 s、261–276 s），音量 0.5，音区行 0–11 | 段落疏密是必须保住的结构信息；全程叠层会浑 |
| R5 去重 | 同一 `(step,row)` 只保留一颗音：旋律优先于低音，同声部保留力度大者 | 276 处撞格、157 颗完全重复；这是唯一"改了必然有效"的一项 |

## 5. 问题 4：音色

### 5.1 原版 harp/bass 的边界

| 项 | harp（sand/dirt/grass 等） | bass（oak_planks/oak_log 等） |
|---|---|---|
| 覆盖 | 25 个 `note`（约两个八度） | 25 个 `note`（约两个八度，整体比 harp 低约两个八度） |
| 力度 | 固定，无 velocity（监听模式才有） | 固定 |
| 延音 | 约 1 秒衰减、无长音保持 | 同样短促 |
| 听感短板 | 高频泛音弱、密集复音时糊；钢琴/弦乐的"连奏"完全没有 | 低频在小音箱上放不出来（项目已经发现，所以监听里给贝斯升八度） |
| 可用的替代/补充 | stone → basedrum、glass → hat（项目已实测）；此外还有 snare/bell/chime/guitar/flute/xylophone/iron_xylophone/cow_bell/didgeridoo/bit/banjo/pling 等方块可切换 | 同左 |

**结论**：只靠 harp+bass 做不出"原曲的味道"，但**只用原版音色也能显著改善**——先加打击乐层（basedrum/hat），再把内声部换成 bell/chime 之类的差异音色，收益高于调折叠参数。

### 5.2 资源包 MVP（如果要做）

1. **只做 2–3 个音色**：钢琴（替换 harp）、低音提琴/合成贝斯（替换 bass）、弦乐 pad（替换 bell/chime）。不要一次做全套打击乐。
2. **最小实现**：每个音色准备 1 个持续音采样（C 音），按 `note` 0–24 用播放速率变调（±2 个八度，速度失真在 2 个八度内人耳可接受）；这样只需要 3 个 ogg 文件。
3. **映射到 note 0–24**：资源包 `sounds.json` 里替换 `block.note_block.harp` / `.bass` / `.bell` 对应的音频文件即可；注意资源包只换音色，**不改音高语义**，所以编排数据不用改。
4. **采样来源与许可证**：只允许 CC0/公有领域音源（如 Freesound CC0 标注、VSCO2 CE 之类），在 `NOTICE.md` 里写清来源与许可证；**不要**直接用原曲切段做采样（版权问题，且与项目"不抄袭"的约束冲突）。
5. **验收**：拿同一段旋律（前 8 小节）用旧/新音色各录一遍，人耳 A/B 判断"能不能听出是钢琴/弦乐"；不需要专业设备。

## 7. 口径与未决事项

**本次实测口径（都可复现）**

- 音符与折叠：`build/styx_helix_notes_v3.csv`（3099 行）+ `src/arrange/arrange-notes.mjs` 的折叠逻辑（复现 0 例不符）。
- 音频侧：`build/styx_helix_full.wav`（mono / 44100 Hz / 16 bit / 281.4 s）。做法是 4096 点 FFT（Hop 2048）＋ Hann 窗 → 分帧 chroma / 窄带能量；网格验证用 1024 点 FFT（Hop 441，10 ms）算 onset 强度。
- 八度标定：对每颗音取起始帧，比较"同音级各八度基频 ±1 半音（含 2 次谐波）"的能量，取最大者为音频八度（旋律限定 131–2093 Hz，贝斯限定 41–523 Hz）。
- MIDI：`build/styx_helix_minecraft.mid`（format 0、单轨、tempo 120、division 480、velocity 全 90、时值全 0.05 拍）。

**未决 / 需要确认**

1. **原曲音频与转谱数据的来源**：`styx_helix_minecraft.mid` 名字与"单轨 / 全部 0.05 拍脉冲 / 全部 velocity 90 / 只用一个音阶"的特征，说明它更像是**别人做的红石音乐机器谱**（或是从别的机器布局反推出来的），而不是原曲演奏转录。要"依照原曲"，建议用官方音源重做一次转录，并在 `NOTICE.md` 说明当前数据的局限。
2. **harp 与 bass 的实发八度差**：需要一次游戏内实测（`/playsound` 或对 `testserver/capture.wav` 做基频测量）来确认，本文只按"相差约两个八度"给建议。
3. **拍长的最终认定**：0.48 s 还是 0.96 s 只影响文档写法，不影响播放；如果要与原曲音轨做视频对拍，需要另做一次"总时长对拍"确认（见 4.1）。
4. **是否引入资源包采样**：需要决定采样来源与许可证，并在 `NOTICE.md` 登记。
