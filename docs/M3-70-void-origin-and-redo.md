# M3-70 · 虚空存档换原点 + redo 链重写（2026-09-22）

用户现象：在 `StyxHelix虚空` 存档跑 `/function styx:redo`，**收到"重做完成"提示，但世界里一个音符盒都没有**
（截图 + "没有成功生成音符盒呢？"）。

## 1. 三个独立故障（都在同一条链上）

### 1.1 `forceload` 还是旧原点 → 区块压根没加载 → `setblock` 静默失败

`src/emit/redo-chain.mjs` 里的强加载窗口写死成旧机器的 `x 480..1103 / 1104..2359 / 2352..2880`、
`z −176..−136`；机器搬到 `215,-82,58` 之后：

- x 方向：窗口 1/2/3 只覆盖 x≥480 → 机器西段（215..479）**永远不在加载范围**；
- z 方向：**三个窗口全都只加载 z −176..−136**，而机器在 z 55..82 → **等于一个区块都没加载**。

`setblock` 对未加载区块不报错、不写日志（函数内静默失败）→ 界面提示"重做完成"，世界零变化。

修法：窗口**从剖面推导**（`single-row-layout.mjs --origin` 的产物），并在生成时断言
`forceload` 不超 256 区块；`undo-clone.mjs`（回退快照的 clone 窗口）与 `wipe-machine-region.mjs`
（清除范围）同步改成推导。

### 1.2 机器原本的 y=−82 在这个存档里**不存在**

用户给的坐标来自 F3 剪贴板（`XYZ 215.9 / −81.13 / 58.05`），但实测：

| 证据 | 结果 |
|---|---|
| `level.dat` 维度类型 | `minecraft:overworld`，由 `2032-world-height-1.1.jar` 提供：`min_y=−64 / height=2096`（**只往上扩到 Y=2031**） |
| 副本服加载同一存档 + 同一 mod 集，`setblock 215 −81 61` | `That position is out of this world!` |
| 同一次实验 `setblock 215 −64 58` / `−63` | `Changed the block …` ✔ |
| 玩家 `playerdata`（16:52 落盘） | `Pos y = −64.38` —— 已经被世界下限"顶"到最底层 |
| 客户端日志 16:50:22 | 传送到 `−76` 之后的位置最终落在 `−64.38` |

结论：这个虚空存档的可建造范围是 **y −64 .. 2031**，`−82` 属于世界之外；玩家现在站着的位置（F3 显示
`Block: 208 -65 70`）就在世界底板那一层。

**处理**：机器原点改成 `215,-62,58`（甲板/触发层 y=−62、音符盒层 y=−61），x/z 与用户指定的一致；
沿整条机器的所有产物（剖面 / apply_notes_v3 / redo 链 / undo 快照 / wipe / mod 的 machine_map）全部按
新原点重新生成。

### 1.3 就算范围对了，**区块加载也是异步的** → 后段照样铺不上

2026-09-22 无头实测（副本服，真存档副本）：

| 做法 | 结果 |
|---|---|
| `tick sprint 1200` 把 640 刻的链压到 1 秒内跑完 | 音符盒 **468/3044**（且早期版本是 0——窗口 3 整段没铺上） |
| 按 20 tps 真节奏跑，但链里只给 `forceload` 后 6~10 秒就 `apply_notes_v3` | 前两窗口基本铺上，**窗口 3（x1783..2566）整段缺失** |
| 链里加入"**等 `if loaded` 为真再铺 + 铺完抽查 3 点、不合格再补两遍**" | **3044/3044，缺 0 多 0** |

原因：这个存档的维度高度 2096 → 每个区块 250+ 个 section，load/generate 明显比普通世界慢；
`forceload add` 只是**排队**，区块不会立刻可用，而 `setblock` 一旦落在未就绪的区块上就静默丢失。

修法（`src/emit/redo-chain.mjs` 重写）：链变成
`s1（修地形+强加载窗口1）→ w1（等 loaded）→ w1go（快照+apply+抽查，缺口就补）→ w1next（切窗口2）→ w2 … → w3next（撤强加载、告诉玩家用 /nbm machine start）`。
抽查点直接从 `apply_notes_v3.mcfunction` 里挑该窗口真实存在的 3 格（首/中/末），不会误报。

## 2. mod 侧三处修复（同一次改动）

`mod/.../machine/NbmachinaMachine.java`：

1. **触发位判据**：旧代码 `strict = ty == y + 1`（只认"水平相邻"），而 M3-68 起触发位记的是
   **音符盒正下方**（`ty == y`）→ 全部被判成"没有严格触发位"→ 走引擎兜底、**红石块根本不放**（音符盒不再发声）。
   现改为几何判据：红石块与音符盒**相邻（曼哈顿距离 1）**才算触发位。
2. **滚动强加载的 z 带**：旧代码写死 `cz = (−200>>4)−1 … (−110>>4)+1`（旧机器的 z 带）→ 新机器 z 55..82
   等于**没被强加载**，曲子走到加载范围外就"没声音"。现从谱面里的 z 推。
3. **红石灯视觉**：旧代码在每颗音到点时往 `y−1` 塞一盏红石灯（为旧机器的灯层设计）；新机器已经没有灯层，
   这会在机器下面**凭空刷出一排灯**。现只保留粒子（视觉增强按用户要求另做 mod）。

## 3. 扫描工具的两个真 bug（`src/scan/mca.mjs`，从 wipe 生成器里抽出来共用）

| bug | 现象 | 修法 |
|---|---|---|
| `sections[].Y` 是**有符号 byte**，NBT 按 unsigned 读出（−4 → 252） | y<0 的方块一律扫不到 → "扫出来 0 个音符盒，游戏里明明有" | 读数时还原符号（>127 减 256） |
| palette 是**按方块状态**去重的，同名会出现多次（`note_block` 至少有 harp/bass 两档） | 只 `findIndex` 命中的那一档被算，另一档全丢 → "铺出 468/3044" | 收集**所有**同名 palette 下标再比对 |

这两个 bug 会让"验收"和"wipe"同时失真（一个说没铺、一个清不干净），所以顺手抽成公共模块并写进注释。
