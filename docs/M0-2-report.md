# M0-2 · 八度证据（T2）+ 用证据修音高（T3）

**一句话**：对 3099 颗音逐音做"音级固定、8 个候选八度"的窄带能量标定，输出 `build/analysis_octave.json`；
再用证据重写 `midi`，得到 `build/notes_fixed.csv`。**相邻两音相差整数八度的错误对从 270 降到 79
（旋律 113→49、贝斯 157→30）**；用与修复无关的第三方判据（谱峰）衡量，贝斯八度正确率
**87.9% → 96.8%**、旋律 **89.4% → 93.6%**。

## 1. 口径（可复现，全部写在 `DEFAULT_CONFIG` 里）

| 项 | 取值 |
|---|---|
| 时间窗 | 从音符起始时刻起 **100ms**（44.1kHz → 4410 采样点），**Hann** 窗；不足补零 |
| 参考音高 | **A4 = 440Hz**（midi 69） |
| 候选八度 | `midi = (输入 midi 的音级) + 12k + 12，k=0..7` → **C0..B7 共 8 个** |
| 窄带能量 | Goertzel（= 该频点加窗 DFT 的功率），一次遍历 O(N) |
| 打分 | `Σ_h w_h · E(f0·h)` |
| 旋律（harp/中高频） | **先谱白化**（除以全曲 LTAS 中位数，下限 = 5% × 各候选谐波频率的 LTAS 均值），再取 1..4 次谐波梳状和，`w = 1, 1/2, 1/3, 1/4` |
| 贝斯（低频） | **不做白化**，直接用基频绝对能量（`h=1`） |
| LTAS | STFT：帧长 4096 / 跳 2048 / 均匀抽 ≤700 帧 / **逐频点取时间维中位数**（本曲 758 帧） |
| 音域先验 | 候选按"音频实测音域"过滤：**贝斯 A0..D#4（midi 21..63）**、**旋律 B2..F#7（midi 47..102）**；取值来自 §3 的第三方谱峰实测分布 |
| 弱证据 | 窗内 RMS < `minRms`（0.01）→ 证据不足 |

> 白化/音域先验这两条不是拍脑袋：见 §3 的口径对照表——贝斯若跟着旋律一起白化，
> 正确率 96.8% → 53.1%；贝斯去掉音域先验，96.8% → 91.4%；旋律白化 93.6% vs 不白化 99.7%
> （后者与基准统计量同源，不宜直接采信，理由见 §3.2）。

## 3. 第三方独立基准（用来验证，不参与修复决策）

**方法**：在同一个音头取 186ms 窗（8192 点 Hann，零填充到 16384），在该声部音域内找**最强谱峰**，
抛物线插值细化频率；若该峰落在"本音 8 个候选八度"之一的 ±60 音分内，就把它当作这个音的独立八度基准
（不同音级至少差 100 音分，所以这条判据很干净）。它和证据用的是不同窗长和不同统计量，
**覆盖 2061/3099（66.5%）**（其余音在这一刻不是窗内最强峰，无法独立判断，不计入）。


### 3.1 分层：修好的是哪一段，坏的是哪一段

| 声部 | 输入 midi 段 | n | 输入原值 | 证据/修复后 |
|---|---|---|---|---|
| 旋律 | 0..59 | 20 | 100.0% | 95.0%（样本太小，只错 1 颗） |
| 旋律 | 60..71 | 283 | 80.6% | **88.7%** |
| 旋律 | 72..83 | 510 | 91.6% | **93.1%** |
| 旋律 | 84..127 | 504 | 91.9% | **96.8%** |
| 贝斯 | 0..23 | 106 | 35.8% | **90.6%** |
| 贝斯 | 24..29 | 119 | 92.4% | **95.0%** |
| 贝斯 | 30..47 | 448 | 97.5% | **98.2%** |
| 贝斯 | 48..127 | 71 | 97.2% | **100.0%** |

**结论：输入的贝斯八度错误集中在 midi ≤ 23（听上去"不在原位"的那一批，只有 35.8% 对）；
midi 30 以上其实大体是对的（97.5%）。** 旋律的问题集中在 midi 60..71 这一档（80.6%）。

### 3.2 口径选择的实证依据（旋律为什么白化、贝斯为什么不白化）

旋律不白化时，候选八度里的低八度会"捡到"同时发声的贝斯/底鼓能量。抽样审计两个口径的
113 颗分歧音（列出前 8 例）：**4 例是原始能量口径被贝斯拉走**——例如 t=20.88s 输入 B4(494Hz)，
同一时刻贝斯在 B2(123Hz)，原始口径判 B2、白化口径判 B4（= 输入原值）；**另 4 例**（两组）是
同一刻本身写了两颗相差八度的重复音（两种判法都说得通，真正的修法是去重，见 §7）。

反过来，贝斯的基频区本来就被自己占满，白化会把"背景"也算成本音（基准 96.8% → 53.1%），所以低频不白化。

> 注：基准表里"全部不白化"的旋律分（99.7%）**明显偏高且不宜直接采信**——那条口径的统计量
> （候选频点上的最大窄带能量）与基准的统计量（音域内最强谱峰）本质是同一件事，等于用同一把尺子
> 量两次；白化口径是唯一与基准不同的口径，它给出的 93.6% 才是有信息量的交叉验证。

## 5. 与 DISCUSSION-C 的差异：贝斯 30.8% 这个数字我复现不出来

音乐组在 `docs/DISCUSSION-C-music.md` 里给出："逐音取该音级在不同八度上的窄带能量：旋律 98.3% 在
转谱八度 ±1 内（86% 完全一致），**贝斯只有 30.8%**（多数差 +2~+3 个八度）"。

- **旋律**：我这条链路给出 89.9% 完全一致 / 98.0% 在 ±1 内 → **与他们的 86% / 98.3% 一致**。
- **贝斯**：我给出 75.2% 完全一致 / 96.6% 在 ±1 内；第三方谱峰基准（与能量口径无关）给出
  **输入 87.9% 正确**（覆盖子集 n=744），其中 midi 30..47 段 97.5% 正确。**30.8% 复现不出来。**

差异最可能来自他们的候选频带：DISCUSSION-C 第 182 行写"贝斯限定 41–523Hz"（= E1..C5，midi 28..72），
而本曲**真实存在 A0–E1（27.5–41Hz）的低音**：修后贝斯有 142 颗（10.4%）落在 midi 21..23，
输入里有 596 颗（43.8%）写在 midi ≤ 29。频带一刀切在 41Hz，会把这一整段（以及任何更低八度的候选）
判成"不一致"，于是"错误率"被放大到七成。方向性结论没错（midi ≤ 23 段输入确实只有 35.8% 正确），
但 **30.8% 这个量级依赖口径，不宜直接引用**；本报告用可复现的两套判据（窄带能量 + 独立谱峰）取代它。

## 6. 降级与保真（degradations）

- 本曲 3099 颗音的窗口 RMS 最小 0.1321、中位 0.1925（阈值 0.01，差一个数量级以上），**没有触发弱证据降级**，
  所以 `degradations[]` 是空的。
- 规则本身不是摆设：单测里用**全静音**音频验证了"证据不足时保留原值 + 写入 degradations"
  （`reason='weak-evidence'`，同时记录 rms）；另有一条用**缺条目**验证 `missing-evidence`。
- 证据是"只改八度、不动音级"的：`newMidi` 与原 `midi` **音级必然相同**（±12k）。音级本身的错误
  （本曲输入只有 7 个音级、chroma 对齐 r=0.87）不在本任务范围，留给音级恢复那一步。

## 7. 交给下游的交接点（重要）

1. **去撞格（T4）**：修八度会把"同一颗音写了两遍、差一个八度"的重复对压回同一个音高。
   统计 `(step, 声部, newMidi)` 重复：**修前 2 组 → 修后 159 组（可合并 159 颗）**。
   这 159 组必须在去撞格/布局前合并掉，否则"数据说有 2 颗、机器只响 1 颗"。
2. **`row` / `volume` 需要重算**：`notes_fixed.csv` 按任务要求"保留原列 + 新 midi"，
   所以 `note_block_pitch` / `octave_shift` 仍是**旧折叠结果**；`--emit-v3` 产出的
   `notes_fixed_v3.csv` 也只改了 `midi`，`row`（折叠到音符盒 0..24）与 `volume` 未重算。
   编曲/折叠步骤必须按 `newMidi` 重新折叠、重新取力度。
3. **机器下限**：音符盒贝斯最低 F#1（midi 30），而修后仍有 435 颗（32%）低于它——这一段是
   **真实存在的低音**（第三方基准也测到 A0/B0），编曲时要显式折叠并出清单，
   不能当成"数据错误"再改回去。

## 8. 已知限制（如实记录）

- 谱峰基准只覆盖 66.5% 的音（其余音在这一刻不是窗内最强峰）。覆盖子集偏向"该音是此刻最响内容"的
  情况，所以 96.8% 是**乐观上界**；未覆盖部分没有独立判据，只能靠证据口径本身。
- 修后仍有 79 对相邻整数八度（旋律 49、贝斯 30）。抽查这类残留属于"同一刻写了两颗相差八度的音"或
  两个音级各占一个八度，**不是本模块能消掉的**：前者要去重（T4），后者要编曲层做声部内 DP 折叠。
- 窗口固定 100ms、从音头起算；没有做音头微对齐（±10ms 搜索在实验里对结果没有稳定改善，故未启用）。
- 低频（<30Hz）候选理论上可判，但已被音域先验排除；若以后要处理 16 尺管风琴类素材，需要改先验而不是改算法。
