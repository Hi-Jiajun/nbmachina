# M3-19 · 低音糊的根因与"放音"机制（2026-09-16）

**用户听感**："低音的部分感觉延音一直都在，低音多了之后就很混乱嘈杂。"

## 1. 根因（有数）

不是采样问题，是**没有任何"放音"**——每颗音都把 10 秒（截断后）的完整采样放满：

| 事实 | 数值 |
|---|---|
| 贝斯声部音符数 | 1276 颗（全曲 278.4s，≈4.6 颗/秒） |
| 其中 midi ≤ 40（E2 以下） | **1054 颗** |
| 这些低音里与上一颗间隔 < 0.5s 的 | **956 颗** |
| 贝斯相邻间隔中位数 | **0.12s** |

→ 同一时刻挂着几十路低音尾巴（低音弦衰减本来就慢），必然糊。
而且这条贝斯线来自**原曲的贝斯/合成器**，不是钢琴左手——钢琴要弹这种密度的低音，
必须像真人一样**换踏板/放音**。

## 2. 机制：放音（damping）

`NbforgeAudio` 新增"声部"概念（协议 `nbforge:play` 增加 `voice` 字段），按两条规则放音：

| 规则 | 触发 | 淡出 | 依据 |
|---|---|---|---|
| **同声部单音线** | `bass`：新音进来时，把同声部还在响的音都放掉 | 120ms | 钢琴换踏板 / 贝斯手换音，低音线本来就不该叠尾巴 |
| **同键重击** | 同一（乐器 + 键位）再次响起 | 60ms | 同一根弦被重新敲响，物理上就是替换上一个声音 |

**和弦保护**：同一 tick 派发下来的和弦（例如 0.12s 内的三个低音）不互相放——只在
"上一个音已经响了 ≥60ms"时才放，否则一个三音和弦会被自己掐成单音。

## 3. 预测（离线模拟同一套规则）

按 `score.csv` 的时间轴模拟 `dampConflicts`：

```
播 2915 颗；放音 2699 次；**非放音并发峰值 29**
（修复前同一份谱面的实测并发峰值是 124 —— 全是低音尾巴）
```

所以复测时 `/nbfc status` 的预期是：**放音 ≈ 2699（整曲放完）**、并发峰值显著低于 124、
被抢声部 0。放音次数不是"错误"，正是它在把糊掉的低音掐掉。

## 4. 复测

```
/nbfc status        # 起始：放音 0
/nbforge score load
/nbforge score play # 听低音：应该从"一直嗡"变成"一颗一颗的拨弦/落键"
/nbfc status        # 放一会儿：放音 N 应持续增长；并发峰值应远小于 124
```

## 5. 还没做的（如实）

- 现在只有 `bass` 走单音线。**旋律和内声部仍保留自然衰减**（钢琴的踏板效果）——
  如果听下来觉得旋律也开始糊，可以给 `harp` 也加"同键重击放音"或者按声部配置淡出时长；
- 放音还是固定 120ms；真实钢琴的放音取决于踏板与音区，后面可以按音区细化（低音更短、高音更长）；
- 断奏（真正的短音）仍未实现——那要等 `sta` 采样接入 + 音符时值信息。
