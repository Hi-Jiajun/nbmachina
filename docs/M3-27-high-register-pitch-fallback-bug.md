# M3-27 · 真凶：高音区（>102）的"行号回退"把 G7/G#7 弹成了 C#3/D3

> 用户 2026-09-18："着重看 4m32-4m44 的这段，有很明显的不同，你没有发现吗？" —— 找到了，而且是个**真 bug**。

## 现象

谱面在这一段是 **G7/G#7（midi 103/104）的高音颤音**（0.1s 一颗，从 264s 一直到 280s，共 20 颗），
原视频的频谱里这一段是 G#5/C#5/C#6/E6 + G#7 一类的音。

而**离线渲染**出来的却是 **C#3(138Hz)/D3(146Hz)/D4/A4** —— 整整低了四个八度、还不在调上。

## 根因

`src/emit/playsound-hifi.mjs` 的 `planHifi()` 里，音高要过一道"资源包合成器"的音域表：

```js
if (Number.isFinite(n.midi) && hasEvent(timbreName, n.midi)) return n.midi;
stats.octaveFallback++;
return midiFromRow(timbreName === 'bass' ? 'bass' : 'harp', n.row);   // ← 42 + row
```

`REGISTERS.strings = 42..102`，而颤音是 **103/104** → 判定"没有采样" → 退回 **`42 + row`**：
`row = midi % 24` = 7/8 → 得到 **midi 49/50 = C#3/D3**。

这道检查是给**资源包合成器**（只有两个八度）用的，但离线渲染用的是**真采样库**（Salamander 覆盖 21..108），
根本不该受这个表限制。实战影响：全曲 **21 颗音**（1 颗在 111s，其余 20 颗在 264–280s 的尾奏颤音）。

## 修法

`planHifi(..., { trustScoreMidi: true })`：把"有没有采样"的判断交给**真正加载的采样库**
（渲染器随后还有 `foldIntoRange(midi, lo, hi)` 兜底），`tools/render-ensemble.mjs` 传入该开关。
数据包/资源包那条链路不受影响（默认仍按老口径，避免动到既有回归）。

验证（单颗音、全频段 40Hz–16kHz）：

| 谱面 | 修前 | 修后 |
|---|---|---|
| midi 104（应为 G#7 3322Hz） | **D3(148Hz)** | **G#7(3398Hz)** ✓ |
| midi 103（应为 G7 3136Hz） | **C#3(138Hz)** | **G7(3180Hz)** ✓ |

与原始视频的对数包络相关：**0.860 → 0.894**。

## 同一轮还修掉的第二个问题：高音区采样的低频垃圾

母版里 **F#7/A7/C8** 这些高音采样自带很强的低频内容（60–300Hz 只比基频低 9~10dB，C8 甚至比基频高 28dB）。
修法：按音高分档高通（`截止 = max(48Hz, 基频/4)`，二阶级联），渲染侧与游戏侧都换成了处理后的库
（见 `_scratch-m3-26/make-hp-samples.ps1`）。单文件实测 60–300Hz/基频：F#7 **−8.7 → −65.1dB**、A7 **−10.3 → −77.8dB**。
