# M3-20 · 更正：谱面就是 Animenz 改编；力度改从视频里量（2026-09-16）

**用户指正**："这个谱子就是 Animenz 写的，肯定应该使用 Animenz 原视频为准啊。"

用户是对的，我之前的判断错了。这篇文档记录错在哪、更正后的证据、以及随之改掉的力度来源。

## 1. 之前错在哪

`tools/align-reference.mjs` 的默认参数是 `--ref <视频>` + `--score <原曲混音>`，
也就是说 M3-6 那次"最佳对齐 r=0.08"比的是 **Animenz 钢琴视频 ↔ 原曲混音（人声+贝斯+鼓）**——
两个本来就不是同一件东西的音频，r=0.08 是必然的，**它不能用来判断谱面来源**。
我据此在日志与对话里写过"谱面与视频不是同一演奏"，这条**作废**。

## 2. 更正后的证据（我们的钢琴渲染 ↔ Animenz 视频）

| 检查 | 结果 |
|---|---|
| 视频总长 / 实际演奏段 | 298.7s / **3.90s–284.25s（280.4s）** |
| 我们谱面 | **278.4s**（差 **0.7%**） |
| 全局 chroma 对齐 | scale **1.005**、lag 5.0s，平均余弦 0.579（基线 0.415） |
| 前 60s 细对齐 | scale 1.015、lag **4.30s**，平均余弦 0.602 |
| 起音密度（分段） | 谱面 2915 颗 vs 视频 1665 个起音，每段比值稳定在 **0.35–0.64**（错位会出现整段对不上） |

⇒ **同一首曲、同一速度、同一织体**，视频开头多一段约 4.3s 的引子；
谱面里的 `bass` 声部就是**左手**（红石谱按乐器通道拆成了 bass），
而 `basedrum/hat`（138 颗）不属于钢琴改编，本曲按"全钢琴"预设跳过。

## 3. 随之改掉的东西：力度来源换人

以前所有力度都是从**原曲混音**量的（`P.audio = build/styx_helix_full.wav`）——
人声、贝斯、鼓都在里面，量出来的"力度"与钢琴演奏的力度**几乎无关**：

```
旧（原曲混音） vs 新（Animenz 视频）逐音力度相关  r = 0.005
```

这也解释了 2026-09-15 你听到"实测力度分配特别不好听"：**它量错了对象**。

**新流程**（以视频为准）：

1. 对齐：`t_video = 1.007 × t_score + 4.30s`；
2. 生成对齐音频：`build/animenz_aligned.wav`（`ffmpeg -ss 4.30 -i 视频 -af atempo=1.007`），
   于是它的时间轴与谱面 1:1；
3. 用同一套 `velocity.mjs --accent` 口径重测：`build/velocity_video.csv`。

**客观对照**：

| 指标 | 旧（混音） | 新（视频） |
|---|---|---|
| 与"视频起音强度"的相关 | +0.105 | **+0.460** |
| 旋律相邻音的力度跳变中位 | ≈0.18 | **0.034**（p90 0.089） |
| 力度分布（p10–p90） | 0.367–0.594 | 0.375–**0.667** |

## 5. 还没做 / 待定

1. 逐音档的 16.7dB 动态范围在游戏内是否过大 → 若偏大，一条命令切乐句级（10.7dB）；
2. 视频里的**踏板/延音**还没有建模（当前靠采样自然衰减 + 放音规则）；
3. 若要以视频为唯一标准，下一步应该是拿视频**逐音校对谱面本身**
   （音高/时值/遗漏音），这需要钢琴转谱模型（MIT 的 `piano_transcription_inference` 已确认可装）。
