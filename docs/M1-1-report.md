# M1-1 实测报告 · 音级恢复（"把被吸附到 C# 自然小调的 5 个调外音级找回来"）

任务书：`docs/superpowers/plans/2026-09-14-nbforge-m1.md` Task 1（任务文件 `nbforge-m1-1.md`）。
数据：`build/notes_fixed_v3.csv`（3099 颗音，T3 八度已修）+ `build/styx_helix_full.wav`（mono 44.1kHz 16bit，281.4s）。

**一句话结论：这一条的验收前提被实测推翻。** 谱面音级**不是**被吸附出来的错音——旋律逐音在
"自身音级 / 上邻半音 / 下邻半音"里 98.7% 由自身胜出；任务书那条"调外音级质量 3.4% → ≥8%"
是 M0-3 的**混音级 folded chroma** 造成的误诊（它把**别的乐器**和**泛音**都算进音级，
见 §3.4 的受控实验：把谱面*自己*合成一遍再量，同一指标也会给出 16.1%）。
按音频证据真正站得住的改动只有 **5 颗音**；按任务书原样放开（任意音级、全部声部）会改 102 颗，
其中 85.3% 是 ±2..±6 个半音——那不是"解吸附"，是把同时响着的别的声部当成了这颗音。

## 1. 口径：每个取值为什么这么定

全部常量在 `DEFAULT_PITCH_FIX_CONFIG`，CLI 可覆盖（`--margin/--min-amplitude/--min-amp-over-rms/--probe/--pc-window/--pc-voices/--comb`）。

| 项 | 取值 | 为什么 |
|---|---|---|
| 候选集合 | `floor(midi/12)*12 + pc`，12 个音级 | 硬约束"只改音级不改八度"：`|new−old| ≤ 11` 且八度折叠索引不变（`stats.octavePreserved.violations = 0`）。八度已由 T3 定稿（0.965），动它会把这一项打下去 |
| 窗长 | 旋律 100ms / 贝斯 120ms（同 T5b） | 任务书要求"与 T5 一致"；M0-3 §T5b 的窗长扫描：低音区一个半音 < 1 个 bin，窗太短会把前一颗音的尾巴算进来 |
| 谐波 | 只用基频 `[1]` | 与 T5b 默认一致；加 2f0 会让"高一个八度的同一音级"（C4 的 2 次谐波 = C5 基频）互相污染，正好破坏八度隔离。`--comb` 可对照 |
| 探针 | f0 与 f0±0.25 bin 取最大 | 单点 Goertzel 有扇形损失：Hann 窗偏 0.5 bin 时只剩 **18% 能量（振幅 42%）**，足以把真实音级压到次强以下。三探针后最坏离最近探针 ≤0.125 bin |
| 判定 | 最强/次强 ≥ **1.6** 且音级 ≠ 原音级 | 任务书给的证据门槛（本模块把它同时用在"12 音级"和"±1 邻居"两种候选集上） |
| 证据门槛 | 窗内 RMS < 0.01 → `weak-evidence`；最强峰基频振幅 < 0.02 或 < 0.1×窗内 RMS → `no-peak` | 挡"八度错了的音"：别的八度上的音在本候选八度只剩旁瓣泄漏（Hann 3 bin 处 ≈ −31.5dB → 振幅等效 0.03–0.04 × 真音），没有这道门槛就会按噪声随机改音级。振幅由能量反推：`A = 4·√E/N`（单测验证 0.25 → 0.25） |
| **音级位移** | **±1 半音以内**（`--pc-window 11` = 任务书原口径） | "吸附到最近的音阶音"位移上限就是 1 个半音。实测按原口径放开，102 条改动里 **±1 只占 15 条（14.7%）**，±3 有 39 条——那些是**别的声部**（见 §3.5）。改 ±3 会直接破坏旋律走向（DISCUSSION-C §2.1 的必保项） |
| **可判声部** | `melody` / `inner`（`--pc-voices` 可放开） | 贝斯（midi 21–63）一个半音 4.3–6.9Hz，而 100–120ms 窗的分辨率是 8.3–10Hz——**一个半音不到一个 bin**。实测贝斯邻居/自身能量比中位 **0.96**（旋律 0.00–0.12），即"上邻半音和自身一样强"，音级不可判；一律保持原值 + `register-ambiguous` |

### 降级的语义（保真契约）

| `reason` | 含义 | 本次计数 |
|---|---|---|
| `evidence` | 改了（最强音级 ≠ 原音级、边距 ≥1.6、振幅门槛通过） | **5** |
| `kept` | 12 音级里最强音级就是原音级（证据支持原值） | 3064 |
| `register-ambiguous` | 该声部（贝斯）本口径下音级不可判 | 1360 |
| `no-peak` | 最强峰振幅不足（疑似八度错/静音段） | 27 |
| `below-margin` | 最强/次强 < 1.6（两个音级差不多强，不猜） | 3 |
| `weak-evidence` | 窗内 RMS < 0.01 | 0 |

## 3. 为什么"5 个调外音级被压制"不是音级错误（四条证据）

### 3.1 谱面源头就是 4 个升号（C# 小调 / E 大调），调外音级本来就少

转谱链路的输入是**谱面图片**（`build/page-01.png`，Animenz 编曲、PianoVI 转谱、♩=123），
不是音频转谱。看图（`build/sys0_left.png` 放大）两行谱表都是 **4 个升号**。
谱面第一小节里那两处"♯/♮"相邻的写法（C# 与 C 天然音并排）也说明转谱是**逐个读了升/还原记号**的。
也就是说：`C/D/F/G/A#` 这 5 个"调外"音级在**这份编曲里本来就只占 3.4%**，不是被吸附掉的。

### 3.2 OMR 中间产物里的 `midi` 是"没套调号的字面拼写"，不是真值

`build/notes.json`（OMR 输出）里每颗音带 `acc`（还原记号）和 `name`，音级分布是
**D:454 G:553 C#:381 F#:368**（= 只套了 2 个升号 F#/C# 的字面拼法），
`D#:0 G#:0`。谱面调号是 4 个升号（§3.1），所以 D#/G# 才是这份谱面应有的拼写——
下游套上 4 个升号得到 v3 谱面（`D#:291 G#:481`）**是对的**，`notes.json` 的 `midi` 才是"没套调号"的那一版。
（两条独立证据都指向同一结论，见 §3.3。）

### 3.3 逐音音频证据：旋律 98.7% 由**自身音级**胜出

§2.5 的诊断在每颗音的数秒窗口里量"自身 / 上邻 / 下邻"三个半音：

- 旋律：**自身赢 1716/1739 = 98.7%**，邻居/自身能量比中位 0.00——音频在这些位置上就是谱面写的音级。
  "被吸附"会造成系统性的邻音胜出，这里没有。
- 对 `D#`（198/200）与 `G#`（293/295）这两组"§3.2 争点"音级，自身赢的比例同样是 98–99%：
  **音频明确支持 4 个升号的拼写**。
- 贝斯：自身赢 52.3%、邻居/自身 0.96 → **不可判**（一个半音 < 1 个 bin），不是"错"。

### 3.4 受控实验：把谱面**自己**合成一遍，同一条指标也会给出 16.1% 的"调外质量"

把 `notes_fixed_v3.csv` 的 2802 颗音按 onset/力度合成一段音频（基频 + 2/3 次谐波 + 0.35s 衰减），
再用**完全相同的**混音级 folded chroma（8192 点窗 / power 折叠 / l1）量它：

| 对象 | "调外"（C/D/F/G/A#）质量 | 余弦 vs 谱面直方图 |
|---|---|---|
| 谱面 count 直方图 | 3.4% | 1.000 |
| **谱面自己合成后再过混音级 chroma** | **16.1%** | 0.9759 |
| 真实音频 | 23.2% | 0.9361 |
| 真实音频 vs 合成谱面 | — | **0.9861** |

读数：**指标本身**（全曲折叠式 chromagram）会把谱面自己的 D#/F#/B 的 2/3 次谐波折到 A#/C/G 等音级上，
凭空造出 16.1% 的"调外质量"；真实音频的 23.2% 只比它多 7 个百分点，那部分是**别的乐器/人声/鼓**
（这份谱面是双行钢琴缩编，不是全band分谱）。所以 "3.4% vs 23%" 的差不是"缺了 20% 的音级"，
而是"缩编谱面 vs 全band混音 + 泛音折叠"的差。余弦 0.9861（真实音频 vs 合成谱面）也说明：
**谱面已经解释了音频音级结构的绝大部分**。

```
  音级迁移（前 12）：G#5→B5 12｜F#5→A5 9｜C#2→C2 7｜C#5→E5 6｜G#5→C#5 5｜B4→G#4 4｜E5→G#5 4｜B4→A4 4｜E5→B5 4｜D#2→C2 3｜C#6→G#6 3｜F#5→B5 3
```

这 102 条的半音位移分布：`+3:29 +2:5 +4:6 +5:11 +6:4 −3:10 −2:12 −5:9 −4:1 −1:13 +1:2`
→ **±1 只有 15 条（14.7%）**，其余 87 条是 ±2..±6。位移 ±3 且成对出现（G#5→B5、F#5→A5、C#5→E5…）
正是"三度叠置"——它们是把**同时响着的另一个声部**（伴奏音、内声部、别的乐器）当成了这颗音。
另外：12 音级里"全局最强音级"与谱面不一致的有 **1006/3099（32.5%）**（旋律 271、贝斯 735），
说明"现场最响的音级"在复音混音里经常不是这颗音自己的——这正是不能拿"最强音级"当"这颗音的音级"的原因。

## 6. 限制与已知边界（如实定级）

1. **没有听测**：本轮所有结论都在客观指标与逐音能量测量层面；`score.mjs` 的 `overall` 仍为 `null`（人耳清单 30% 未录）。
2. **"最强音级"不等于"这颗音的音级"**：复音混音里 32.5% 的音符现场最强音级不是自己（§3.5）。本模块用 ±1 + 边距 + 振幅门槛把这个坑限制住了，但**没有更根本的解法**（需要声源分离或分谱音轨）。
3. **贝斯音级不可判**（一个半音 < 1 个 bin，邻居/自身中位 0.96）。我另外做了"稀疏段 + 长窗"实验（单测里可复现）：全曲 10% 最稀疏的贝斯音，用 **300ms** 窗时自身赢 87.8%、邻居/自身 0.682——说明**音频允许判的地方也支持谱面**；但这条路径只覆盖 139 颗音，不能推广到全曲，所以默认不动贝斯。
4. **`与 T2 独立证据一致 4.7%`** 是 `score.mjs` 与 T2 产物对不齐（midi 键不一致 → 退化成行号）造成的假象，基线就有（4.2%），与音级改动无关。修法见 §7.4。
5. **`docs/M0-3-report.md` §3.1 的"音级吸附"结论应视为被本报告取代**：那份结论来自混音级 chroma 的相对占比，未扣除（a）泛音折叠、（b）缩编谱面 vs 全band混音的乐器差、（c）宽带底噪。M0-3 §6 第 1 条"音级修复（M1 首要）"这一优先级也应下调。
6. **`note_block_pitch` / `octave_shift` 两列在交付 CSV 里保持原样（陈旧值）**：与 T3 的做法一致，折叠由流水线的 `fold.mjs` 按 `midi` 重算（本次 2805 颗音全部重折、撞格 0）。

## 7. 下一步建议（按优先级）

1. **M1-1 收口**：把本模块接进 `machine-pipeline.mjs`（或 `npm run arrange` 的 T1 位置）作为**可选步骤**，默认 `pcFixVoices=melody/inner`、`maxPcShift=1`；V1 的口径**不要**接进默认链路。
2. **换掉那条验收指标**：把"混音级 chroma 的调外质量"换成①§2.5 的逐音邻居支持（自身赢比例），②`--neighbor-check` 的逐音级胜率表，③`score.mjs` 的 `octaveHit / noteSupport`。这三条都不会被泛音折叠与别的乐器污染。
3. **听感问题的真正落点**：既然音级不是错音来源，剩下的听感缺陷按证据排序是——(a) **去撞格丢音**（v3 3099 → machine 2802，漏音 9.4%，M0-3 §3.5）；(b) 长音/延音（M1-2）；(c) 力度不是重音（M1-3）；(d) 八度残余 3.5%（T3 已 0.965）。(b)(c) 两条已有任务，建议优先看 (a)。
4. **顺手修 `score.mjs` 的 T2 对拍**：键改成 `step|time|instrument|原midi` 或用 T3 的 `notes_fixed.csv`（带 `newMidi`）重算一份证据，否则这一行永远是 4% 的假数。
5. 若以后要**真的**补那 5 个调外音级：那是"**补内声部/别的乐器**"的编曲任务（音频 → 新增音符），不是改现有音符的音级；以及可以考虑把 OMR 的音名（`notes.json` 的 `name`）与调号一起读进来做二次校核（本报告 §3.2 的 `midi` 字段不可直接信）。
